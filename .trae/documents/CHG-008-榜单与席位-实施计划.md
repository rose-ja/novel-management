# CHG-008 榜单与席位 — 实施计划（F1）

## Context

CHG-001～007 已交付并归档（HEAD `8a793fe`，DB 迁移 v7）。系统已有人物、势力、地点与回收站/撤销/快照基座，但榜单仍是空壳：`/rankings` 无路由、无后端代码，人物列表/详情、势力成员表的「榜单」列恒为「—」。

CHG-008 要交付一条可走通的垂直切片：创建榜单并生成 1..N 固定席位；指派/移动到空席/交换/移出人物；席位备注；扩容/缩容；人物详情与列表同步名次；整榜软删除、8 秒撤销、回收站恢复（恢复时校验原席位人物仍存在）；人物删除被「榜单席位」阻止（含回收站中的榜单）。

依据：`project/roadmap.md` §CHG-008、`project/specs/rankings/specs.md` SPEC-RANK-001~004、`project/page-specs/PG-08-ranking-list.md`、`PG-09-ranking-detail.md`、`project/api-contract.md` §3.6、`project/data-model.md` §3.6/§3.7、requirements FR-17~20 / AC-06、AC-09、AC-13、AC-14 / EX-17、EX-19、EX-20。

## 已确认决策

| ID | 决策 | 说明 |
|---|---|---|
| D1 | 校对确认端点延后 CHG-011 | 与 CHG-006/007 一致；本轮只读 `review_status`、显示「待校对」Badge 与筛选，不实现 `POST /rankings/{id}/review`（用户已确认） |
| D2 | 名次三处回显 | 人物详情、人物列表、势力成员表统一显示 `榜单名·第N席`（最多 2 条 + `+N`）；复用 `Characters.Summaries`（用户已确认） |
| D3 | 席位即固定行 | 建榜批量生成 1..N 行；空席保留可见；缩容只物理删除尾部空席；席位无独立软删列，随榜单可见性联动 |
| D4 | 席位并发 | `If-Match` 取席位 `version`；锁顺序：作品行锁 → `pg_advisory_xact_lock(hashtext(ranking_id))` → 榜单行锁 → 席位行锁；交换先双席置空再回写，规避部分唯一索引 |
| D5 | 移出榜单撤销 | 契约无 seat undo 端点，采用前端 8 秒内存快照 + 再 `PUT` 回填（best-effort，409 时提示席位已变化） |
| D6 | 删除榜单 | 整榜软删除、席位行保留、返回 8 秒 `undo_token`；`If-Match` 可选（前端始终传 version） |

### 第 3 步：服务（T3）

新增 `internal/service/rankings.go`，注册 `RootTypeRanking = "ranking"`：
- `List`：`work_id` 必填；`q`、`review_status`、`sort`（`updated_at:desc` 默认、`name:asc`）、20/页；装配 `occupied_count/empty_count/top_seats`（前三席）。
- `Create`：名称 1–200、同作品唯一（大小写等价）、`seat_count` 1–200；同事务插入榜单 + 1..N 空席。
- `Get`：榜单摘要 + summary + 席位分页（默认 50，仅允许 50/100，其余 422）；席位人物批量用 `Characters.Summaries` 装配头像/境界/势力。
- `Update`：名称/`seat_count` 子集 + `If-Match`；扩容 `generate_series` 追加空席；缩容先查 `seat_no > target` 的占用，命中返回 `SEAT_SHRINK_OCCUPIED`（details 固定 `{from_seat_count,to_seat_count,items[{seat_no,character_id,name}]}`），否则删尾部并更新 `seat_count`。
- `Delete`：锁后软删榜单，返回 `undo_token`，席位保留。
- `PutSeat`：`character_id=null` 清空并清备注；否则校验人物同作品活跃、同榜重复指派 → `SEAT_CONFLICT`；备注与人物同一条 UPDATE；返回新席位 `version`。
- `MoveSeat`：`mode=empty|swap`；源 version 校验；目标越界 → `SEAT_OUT_OF_RANGE`；`empty` 且目标已占 → `SEAT_CONFLICT`；交换先两席 `character_id=NULL` 再分别回写，原子完成。
- `ListSeats`：`page/page_size/occupied` 透传。
- 错误 details 形状在 F1 `design.md` 冻结。

## 风险与回滚

| 风险 | 对策 |
|---|---|
| 交换触发 `seats_character_uq` | 先两席置空再回写；锁两行；集成用例覆盖 |
| 作品永久删除被席位 FK 阻断 | 所有 purge 路径先删 seats 再删 rankings；`PurgeAllDeleted` 同 scope |
| 回收站榜单仍引用人物导致删除被误放行 | 引用查询不过滤 `deleted_at`；Purge 前复核 |
| 缩容并发与席位写入交错 | 作品行锁 → ranking advisory → 榜单/席位行锁；缩容与 PUT 同序 |
| 移出撤销破坏他人修改 | 前端快照 + version 校验，409 时只提示 |
| 迁移 Down 丢数据 | Down 仅用于集成往返；迁移前快照 |

回滚：回退代码与 `0008` 迁移（Down 删两表）；导航与人物列隐藏；业务数据可从迁移前快照恢复；不影响人物/势力/地点。
