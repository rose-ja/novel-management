# CHG-009 快速搜索与条件检索 — 实施计划

## Context

CHG-001～008 已交付（迁移 v8）。CHG-009 目标是按 SPEC-SEARCH-001~005、PG-01、API 契约 §3.9 与 requirements FR-27~33 / AC-08 / AC-23，提供当前作品内的统一检索入口：人物、势力、地点、榜单、体系节点；支持别名/称号/简介/关联实体名命中、条件 AND 筛选、分组结果、命中摘要与高亮、全局 20 条分页、空/无结果/错误态，并保证回收站与跨作品数据不进入结果。

当前代码没有 `search_documents` 表、`internal/search` 包、`/search` 路由与页面。本计划新增这些能力，并保持不新增第三方依赖。

## 核心设计

### 1. 数据与索引（迁移 0009）

新增 `search_documents`，字段按 data-model §3.15，并补一列 `review_status`（存 DB 值 `reviewed|pending`，供条件检索与结果 Badge 使用）：

- `id TEXT(26)`：内部不透明 ID，SQL 侧用 `substr(replace(gen_random_uuid()::text,'-',''),1,26)` 生成。
- `work_id` FK `works(id) ON DELETE CASCADE`；`entity_type` CHECK 五类；唯一 `(work_id, entity_type, entity_id)`。
- `name_text/name_key/alias_text/title_text/desc_text/relation_text/updated_at/is_deleted/review_status`。
- 索引：`(work_id, entity_type, is_deleted)`；`name_text/alias_text/title_text/desc_text/relation_text` 各自 `GIN (… gin_trgm_ops) WHERE is_deleted = false`。
- 0001 已启用 `pg_trgm`，0009 不重复创建扩展。

### 2. 检索文档刷新（`backend/internal/search`）

- `Refresher.RefreshWork(ctx, tx, workID)`：在同一事务内用 5 条集合式 `INSERT … SELECT … ON CONFLICT (work_id,entity_type,entity_id) DO UPDATE` 重建该作品全部文档。
  - 每类实体用 LATERAL/相关子查询先聚合成一行，避免多别名×多地点×多榜单导致的笛卡尔积。
  - 包含软删除实体，`is_deleted = (实体.deleted_at IS NOT NULL OR works.deleted_at IS NOT NULL)`；`review_status` 同步。
  - `relation_text` 只聚合**活跃**关联实体名：人物→势力/地点/榜单/体系节点（含父节点与类别名）；势力→上级/首领；地点→上级/关联人物/势力；榜单→在榜人物；体系节点→类别/父节点。
  - 最后删除源实体已物理不存在的同作品文档（5 类 `NOT EXISTS` 清理）。
  - `DO UPDATE … WHERE` 仅在任一文本/is_deleted/review_status 变化时更新，减少 GIN 抖动。
- `RebuildAll(ctx)`：全量重建（启动时执行一次，兼容 v8 升级数据；CLI reindex 复用）。
- `Consistency(ctx, workID)`：按类型比较文档数与源实体数，返回漂移明细。
- 写放大取舍：本变更采用“整作品重建”保证 SEARCH-005 的一致性；作品规模上限约 1500 文档，写侧可接受。若后续写 P95 不达标，再在 CHG-012 切换为 `RefreshEntity` + 引用方增量刷新（设计文档记录回滚路径）。

接入点（均在原事务末尾调用 `RefreshWork`）：

| 服务 | 方法 |
|---|---|
| characters | Create、Update、Delete |
| factions | Create、Update、Delete（首领/上级变化同时影响人物 relation_text） |
| locations | Create、Update、Delete、AddFaction、RemoveFaction |
| rankings | Create、Update、Delete、PutSeat |
| system | UpdateCategory、DeleteCategory、CreateNode、UpdateNode、DeleteNode |
| trash | Restore、Undo、Purge、PurgeAll（按受影响 work 重建） |
| works | 恢复作品时重建；Purge 由 FK 级联清理 |

- 无事务的写方法（如部分地点关系/体系节点方法）先补 `tx` 包裹再刷新。
- `cmd/server/main.go` 启动迁移后调用 `RebuildAll`（失败仅记录日志，不阻断启动）。

### 3. 检索查询与 API

`GET /api/v1/search`（`httpapi/search.go` + `service/search.go` + `search/query.go`）：

- Query：`work_id`（必填）、`q`（≤200 字符）、`entity_types`（逗号分隔，默认五类）、`faction_id`、`faction_scope=direct|subtree`（默认 direct）、`system_category_id`、`system_node_id`、`location_id`、`ranking_id`、`review_status=pending|confirmed`、`page`。
- 空查询：`q` 为空且无收窄筛选（faction/system_category/system_node/location/ranking/review_status 均空）→ `400 VALIDATION_ERROR`；仅选实体类型不算收窄。
- 分词：`strings.Fields(q)`，词间 AND；每词对 `name/alias/title/desc/relation` 任一字段 `ILIKE '%token%'`；转义 `% _ \` 并使用 `ESCAPE '\'`；英文不区分大小写。
- 评分：名称 4 > 别名/称号 3 > 简介 2 > 关联实体 1；排序 `score DESC, updated_at DESC, id ASC`；全局分页固定 20（`page` 越界返回空 items，组头仍给组总数）。
- 筛选：仅对适用类型生效；`faction_id` 用 `characters.faction_id`，`subtree` 走 `factions` 递归 CTE；`system_node_id` 匹配节点自身及其直接子节点；`system_category_id` 匹配引用该类别任一节点的人物；`location_id` 匹配 `character_locations`；`ranking_id` 匹配席位；`review_status` 对五类生效。
- 筛选 ID 校验：必须存在、属于当前作品、未删除；失效返回 `422 VALIDATION_ERROR`，details 含 `field/value`，前端移除该 chip 并提示。
- 响应 `SearchResult` 按契约 §2.7：`groups[].total` 为组总命中，`groups[].items` 为当前页切片；顶层 `total/page/page_size/query`；item 含 `entity_id/entity_type/title/subtitle/matched_fields/snippet/score/updated_at/url`，人物额外 `image_thumb_url`、`review_status`。
  - `matched_fields`：逐字段检测命中词，`field ∈ name|alias|title|desc|relation`，`matched_text` 取字段内首个命中窗口（≤60 rune，超长加省略号）。
  - `subtitle`：人物“人物 · 势力 · 境界摘要”，势力“势力 · 上级/首领”，地点“地点 · 类型 · 上级”，榜单“榜单 · N 席 · M 人在榜”，节点“体系节点 · 类别 · 父级”；当前页按类型批量补查，禁止 N+1。
  - `url`：`/characters?id=`、`/factions?id=`、`/locations?id=`、`/rankings?id=`、`/system?category=<category_id>&node=<node_id>`。
- 响应头 `X-Cache: BYPASS`（当前未启用检索缓存，语义为缓存关闭）。
- 错误：`work_id` 缺失/作品不存在 → `404` 或 `422`；非法类型/参数 → `422`；空查询 → `400 VALIDATION_ERROR`。

### 4. CLI

`cmd/cli/main.go` 新增：

- `reindex`：获取 advisory lock（与 app 一致，运行中提示 `APP_RUNNING`），全量重建并输出各类文档数。
- `reindex --check`：只做一致性检查，漂移时输出明细并以非 0 退出，不修改数据。

### 5. 前端 `/search`

新增：

- `app/search/page.tsx`：Suspense + `SearchRoute`。
- `components/search/`：`search-route.tsx`（URL 查询参数 ↔ 状态）、`search-page.tsx`、`search-mode-switch.tsx`、`quick-search-bar.tsx`、`conditional-filter-panel.tsx`、`search-result-group.tsx`、`search-result-row.tsx`、`matched-snippet.tsx`。
- `lib/api/search.ts`：类型与 `searchEntities()`。
- `lib/search.ts`：URL 状态解析/序列化、筛选适用性、分组顺序等纯函数（配单测）。

行为：

- 快速搜索默认；输入框 autofocus；1 字符可搜；300ms 防抖；Enter 立即搜；`compositionstart/end` 期间不触发。
- 条件模式：实体类型=全部/非人物时隐藏人物筛选；单筛选下拉用现有 `Select` + 层级路径标签（当前无 TreeSelect 组件，F1 记录为设计系统简化）；势力筛选增加“直属/含下级”选择；活跃筛选 chip 可单独移除；“重置”清空关键词与筛选。
- 请求用 AbortController + 序号丢弃过期响应；加载时结果区 6 行 Skeleton，保留输入。
- 结果：按人物→势力→地点→榜单→体系节点分组；组头显示组总命中 Badge；行内显示命中字段标签 + `<mark>{matched_text}</mark>`；整行为链接；分页保留关键词/模式/筛选并滚动到结果区顶部。
- 状态：无作品页面级空态且搜索框禁用；空查询提示与示例；无结果提示 + 清除筛选；错误 Alert + 重试保留输入；URL 参数固化检索态，浏览器返回可恢复。
- a11y：可见标签“检索关键词”、`section + aria-labelledby`、`aria-live` 播报总数、`aria-busy`、chip 移除按钮 aria-label、`<mark>` 不只靠颜色、Tab/Enter/Esc 可用。
- 导航：`GlobalNav` 在“资料”组首位新增“检索”（`/search`）。不改变现有 `/` 概览默认页（PG-01 原“默认页”按现行壳层保留 `/`，作为 F1 记录的偏差）。
- `/system` 支持 `?category=&node=` 深链：新增 `system-route.tsx` 读取参数并选中类别/定位节点，供检索结果跳转。

## 风险与回滚

- 全量重建写放大：以 `DO UPDATE … WHERE` 降抖，记录写侧观察；不达标时切换增量刷新（回滚路径）。
- 集合 SQL 行放大：所有关联用聚合子查询，测试覆盖多关系。
- 分页稳定性：固定 `score/updated_at/id` 排序；数据更新跨页的极端情况按 RT-06 记录为已知限制，F10 同步 Spec。
- 失效筛选：后端 422 + 前端移除 chip 重试一次；避免静默忽略。
- 系统节点链接：实现 `/system?category&node` 深链；若现有 SystemPage 结构调整成本高，则降级为 `/system?category=` 并在 F1 记录。
- 回滚：代码回退 + `0009` down（删除表与索引）；无业务数据破坏；启动时 RebuildAll 可从源表恢复文档。
