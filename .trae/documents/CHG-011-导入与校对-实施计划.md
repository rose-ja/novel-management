# CHG-011 飞书《正文》迁移导入与校对 — 实施计划

## Context

CHG-001～010 已交付并推送（`83e5547`），当前迁移 v10。CHG-011 要让用户把飞书《正文》按固定模板迁移到新作品：上传 Markdown + 图片 zip → 后台解析校验 → 预览错误与计数 → 快照 → 原子写入 → 导入报告 → 逐条/批量校对。关联 SPEC-MIG-001～005、PG-11、AC-10/11/18～21/25/31。

现状：实体表与 DTO 已含 `review_status/reviewed_at/reviewed_by`，列表已支持 `review_status` 筛选，前端已有「待校对」Badge；但导入全流程、`/import` 页面与 review 接口均不存在。模板 v1.0 未在仓库定义，需要本变更设计并内置下载。

## 已确认决策

| ID | 决策 |
|---|---|
| D1 | 上传两个文件（Markdown + 可选图片 zip），不接受把 Markdown 塞进 zip；md ≤20MB、zip ≤6GB、单图 ≤10MB，仅 jpg/png/webp |
| D2 | 未引用的「多余图片」进入错误清单并**阻断导入**（用户 2026-11-15 确认，PG11-Q6） |
| D3 | 导入成功后**自动切换当前作品**到新作品（用户 2026-11-15 确认，PG11-Q2） |
| D4 | 导入目标固定为新作品；提交前 `Snapshot.Create(reason=import)`，失败即中止 |
| D5 | 图片在事务前落盘到 `images/{work_id}/`，DB 单事务写入；失败删除本次图片与 staging |
| D6 | commit 同步执行并返回 `completed + report`（对齐 api-contract §3.11），前端显示不确定阶段进度；120 分钟超时 |
| D7 | 同一时间仅一个导入；重复 commit 幂等返回同一报告；`uploaded→validating→validated/failed`，提交中 `running` |
| D8 | 校对仅覆盖人物/势力/地点/榜单/体系节点；导入后 `review_status=pending`、`reviewed_by='import'`；确认后 DB 写 `reviewed`、API 返回 `confirmed`、`reviewed_by='local-author'`，版本 +1 |
| D9 | 批量校对：已 confirmed 计 `skipped`；ID 不存在/已删除整批失败（`REVIEW_NOT_FOUND`） |
| D10 | review 响应统一返回 `{entity_type,id,review_status,reviewed_at,reviewed_by,version}`；F10 回写 api-contract 说明 |

## 模板 v1.0 语法（本变更定义）

固定区块顺序：作品信息、体系类别、体系节点、势力、地点、人物、榜单、大事记。`##` 为区块；`###` 起一条实体记录；`键：值` 为字段；`；` 分隔多值；` | ` 分隔关系备注；`>` 表示两级路径；`-` 表示空；以 `| ` 开头的行续接上一字段（多行简介）。未知区块/字段、缺失必填、重复名称、坏引用均报 `{line, field, code, message}`。

```md
# 小说设定导入模板 v1.0
模板版本：1.0

## 作品信息
名称：山海志异
简介：山海之间，万族林立。

## 体系类别
境界（内置）
职阶

## 体系节点
[境界] 炼气
[境界] 炼气 > 炼气一层
[职阶] 学徒

## 势力
### 山海妖族
上级：-
首领：司空摘天
简介：…

## 地点
### 青丘
上级：-
类型：秘境
势力：山海妖族 | 栖息地

## 人物
### 司空摘天
别名：摘天；司空
称号：摘星者
境界：炼气 > 炼气一层
职阶：学徒
势力：山海妖族
地点：青丘 | 故乡；天枢院
图片：images/sikong.jpg
简介：…

## 榜单
### 天骄榜
席位数：100
第1席：司空摘天
第2席：姜黎 | 暂代

## 大事记
### 初入青丘
归属：人物
对象：司空摘天
时间：元启三年 · 春
内容：…
```

- `体系类别`：未声明「境界」时仍创建空内置境界；类别合计 ≤10；非「境界」均建为 normal；类别不参与 review。
- `体系节点`：父必须先于子；同级重名报错；两层上限。
- 人物中除保留字段外的键若命中已声明类别名，即写 `character_system_refs`；`势力` 写 `faction_id`；`地点` 写 `character_locations`；`图片` 只允许一张。
- 榜单席位号 1..200；同一人物同榜重复报错；`席位数` 缺省取最大席位。
- 大事记 `归属` ∈ 人物/势力，对象必须存在。
- 「类型」等自由文本（如 `弟子`/`属下`）按需求只记录为 warning，不建立引用。

## 后端改动

### 迁移与模型

- 新增 `backend/internal/migrations/0011_import_runs.sql`，`LatestVersion` 改为 11；`migrations_test.go` 增加 0011 往返断言。
- 表字段：`id, status, stage, markdown_name, archive_name, markdown_path, archive_path, markdown_bytes, archive_bytes, template_version, work_name, work_id, snapshot_id, counts_json, errors_json, warnings_json, report_json, error_count, error_code, created_at, updated_at, finished_at`；status CHECK 六态；索引 `(status, created_at DESC)`、`(created_at DESC)`。
- 新增 `backend/internal/model/import.go`：`ImportRun`、状态/错误码常量、`ImportCounts/ImportIssue/ImportReport`。
- `model/errors.go` 增 `ErrReviewNotFound`、`ErrReviewInvalidState`；service 增 `ErrImportInProgress/ErrImportStateConflict/ErrImportInsufficientStorage/ErrImportTimeout`。

### 解析与校验包

新增 `backend/internal/imports/`：

- `template.go` + `template-v1.0.md` + `example-v1.0.md`（`//go:embed`）：`TemplateVersion="1.0"`、`Markdown()`、`ExampleZip()`（内置 1×1 PNG）。
- `parser.go`：`Parse(md []byte) (*Spec, []Issue)` 纯函数；按区块解析作品/类别/节点/势力/地点/人物/榜单/大事记；保留行号。
- `validate.go`：`Validate(spec, images) (counts, errors, warnings)`；名称唯一、体系类别/节点、引用、图片匹配、字段长度、层级、作品名重名由 service 补充。
- `images.go`：`InventoryZip(path)`（条目名/大小/前 512 字节 MIME）、`Match(spec, inventory)`（缺失/多余/格式/超 10MB）；复用 `backup.SafeJoin`、`backup.ReadZipFile`。
- `report.go`：报告 DTO。

### 服务与仓储

- `internal/repository/imports.go`：`Insert/Get/GetForUpdate/Update/Active/MarkInterrupted`（参考 `repository/exports.go`）。
- `internal/service/import.go`：
  - `NewImport(db, cfg, log, snapshots)`。
  - `CreateUpload(ctx, markdown, archive)`：流式落 `DATA_DIR/tmp/imports/{id}/`；`backup.AvailableBytes` 预检；插入 `uploaded`；返回记录。
  - `RunValidate(ctx, id)`：`validating` → 解析/校验/图片匹配 → `validated`（含错误）或 `failed`（系统错误）；写 counts/errors/warnings。
  - `Commit(ctx, id, workName)`：行锁；completed 幂等；校验状态与 error_count；预生成 workID；`Snapshot.Create(import)`；读图并 `encodeImage` 落 `images/{workID}/`；单事务直插 work（不建默认境界）→ 类别 → 节点 → 势力 → 地点 → 人物/别名/体系引用/地点关系 → 首领回填 → 地点-势力 → 榜单+席位 → 大事记 → media_assets → `search.NewRefresher(tx).RefreshWork` → `SetCurrentWork`；失败删除本次图片目录与 staging；成功清理 staging 并写 `completed/report_json`。
  - `MarkInterrupted`、`cleanupStaging`；`context.WithTimeout(ImportTimeoutMin)`。
- `internal/service/review.go`：`Confirm(ctx, resource, id)`、`BatchConfirm(ctx, input)`；映射 5 类表；`UPDATE ... SET review_status='reviewed', reviewed_at, reviewed_by='local-author', version=version+1`；同事务 `RefreshWork`；批量先查存在性，confirmed 计 skipped。

### HTTP 与装配

- `internal/httpapi/imports.go`：
  - `GET /imports/template` → `text/markdown` 附件；`GET /imports/template/example` → zip。
  - `POST /imports` multipart（`markdown`、`archive`）→ 202 `{import_id,status}`，后台 `go RunValidate`。
  - `POST /imports/{id}/validate` → 202 重跑校验。
  - `GET /imports/{id}`、`GET /imports/{id}/report`。
  - `POST /imports/{id}/commit` → 200 `{status,work_id,report,review_url}`。
- `internal/httpapi/reviews.go`：`POST /{resource}/{id}/review`、`POST /reviews/batch`。
- `httpapi/router.go` 增 `Imports`、`Reviews`；`cmd/server/main.go` 装配并 `MarkInterrupted`；`request.go` 增错误映射（`IMPORT_IN_PROGRESS/IMPORT_STATE_CONFLICT/IMPORT_INSUFFICIENT_STORAGE/IMPORT_TIMEOUT/IMPORT_INVALID/REVIEW_NOT_FOUND/REVIEW_INVALID_STATE`）。

## 风险与文档回写

- 6GB 流式上传、120 分钟长请求、单事务大批量插入是主要风险；用分块上传、`ExtractZip`/`ReadZipFile` 限额、批量 `CreateInBatches` 缓解。
- 无未裁决硬冲突；api-contract 与 ADR-005 的 `/validate` 差异通过「上传后自动校验 + 保留重校验端点」兼容。
- F10 回写：`data-model.md §3.16`、`api-contract.md §3.11/3.14`、`PG-11`（Q2/Q6 已确认）、`specs/migration/specs.md` 状态、`roadmap.md` CHG-011 进度、`verification/acceptance/pr`。
