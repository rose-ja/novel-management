## 1. 项目背景

### 1.1 背景

写小说时，人物、人物图片、境界、称号、所属势力、地点、势力成员、排行榜等信息分散在飞书文档中，依靠标题层级、括号备注和列表混合表达。随着设定增多，出现三个问题：

1. 查找成本高：确认一个角色的势力、境界或榜单名次，需要在多个章节和列表之间翻找。
2. 同一实体多名称：一个角色可能同时拥有本名、化名、称号和境界描述，例如「司空摘天（神逆）（山海帝君）（帝境五重天）」，没有统一的主名称与检索入口。
3. 修改容易不一致：改名、换势力、调整境界后，需要人工同步多处，容易产生矛盾设定。

### 1.2 核心问题

- 把散落的设定变成可检索、可关联、可维护的结构化资料。
- 保证同一实体只有一份权威数据，修改后所有关联位置自动同步。
- 让多本小说各自拥有独立世界观，又不互相污染。

### 1.3 产品定位

小说设定的结构化资料库 + 检索与一致性维护工具。

它不是：小说正文写作工具、关系图谱或可视化大屏、多人协作平台、AI 内容生成工具。

### 1.4 目标与成功标准

| 目标 | 成功标准 | 验收方式 |
|---|---|---|
| 查得到 | 输入任意本名、别名或称号，一次检索即可定位人物，并看到境界、势力与所在榜单 | 用 20–30 条真实人物样例逐条验证 |
| 改一处全局同步 | 改名、换势力、改境界后，所有关联页面自动更新 | 至少验证三类修改，检查人物页、势力页、榜单页 |
| 迁移完整 | 飞书《正文》与文档内现有配图的人物、势力、地点、榜单、体系、图片完整进入系统，层级可追溯（素材库不纳入本版） | 迁移清单逐项核对；图片数量一致；抽查层级 |
| 替代飞书日常使用 | 完成一次真实创作准备流程，全程不打开飞书查设定 | 用户实际试用并确认 |
| 详情页完整 | 核心资料完整；关系双向可跳转；人物与势力有手工大事记；无死链 | 逐页检查 |
| 检索可用 | 预设查询集返回正确条目、摘要与出处；无匹配明确提示；不编造 | 预设查询集逐条验收 |
| 数据可恢复 | 全量导出后可在空环境恢复；迁移前有可用快照 | 执行一次完整恢复演练 |

### 1.5 输入事实（来自飞书《正文》）

- 文档性质：世界观设定集，不是小说正文。
- 已包含六类内容：纪元史、星空地理、星曜 / 星命 / 十五境体系、三张榜单、万族传（种族 / 势力 / 分支 / 首领）、人物与配图。
- 三张榜单：封神榜、草黄纸、星火榜，飞书现状为 1–100 的固定席位，目前基本为空；产品支持自定义席位数（见 3.5，默认 100）。
- 人物是多值实体：可同时拥有本名、化名、称号、境界（含重天等子层级），并归属某个势力或分支。
- 势力存在层级：万族 → 族 → 分支，分支下有首领与成员。
- 文档中已有真实人物配图，人物图片是实际需求。
- 当前信息依靠「标题层级 + 括号备注 + 列表」混合表达，没有统一字段。

### 1.6 项目约束

| 类别 | 约束 |
|---|---|
| 使用形态 | 单用户；本地 Docker Desktop 运行；桌面浏览器访问；未来可部署公网 |
| 成本 | 第一版零成本优先：不采购云服务器、域名、对象存储或付费 API |
| 数据 | 本地存储；个人创作数据按私密数据处理；必须可导出 / 备份 |
| 迁移 | 仅迁移飞书《正文》与文档内现有配图；素材库不纳入本版；全量结构化 + 人工校对 |
| 范围 | 四类核心对象结构化；不做图谱、正文、协作、移动端、AI 生成、自动排名 |
| 技术 | 技术栈 `TBD`；必须可在 Docker 中运行；不引入云端大模型；不引入持续付费依赖 |
| 界面 | 浅绿色渐变、简洁；中文；桌面优先；不以视觉牺牲检索效率 |

## 2. 用户角色与权限

### 2.1 主用户

项目发起人本人：会同时构思多本小说、每本拥有独立世界观的个人作者。

用户特征：已有大量飞书设定资料；能使用 Docker Desktop，接受本地部署与命令行启动；愿意在迁移后做人工校对；追求零成本；对详情页完整性与视觉整洁有明确要求。

### 2.2 角色与权限矩阵

| 角色 | 本版是否存在 | 权限 | 说明 |
|---|---|---|---|
| 作者（唯一用户） | 是 | 全部功能 | 无登录、无用户表、无角色判断 |
| 只读访客 | 否 | N/A | 未来公网阶段再定 |
| 协作者 | 否 | N/A | 非目标用户，本版不实现 |
| 其他公开注册作者 | 否 | N/A | 多租户与运营不在本版 |

### 2.3 权限边界

- 本版无登录页、无用户表、无角色与权限判断。
- 服务只监听 `127.0.0.1`，局域网其他设备不可访问。
- 公网访问口令不进入本版，仅作为未来公网部署的架构扩展点。
- 「权限不足」在本版直接记为 N/A；未来公网部署时必须增加访问控制。
- 小说设定与人物图片默认私有、默认本地存储；未经用户批准不得上传到任何外部服务。

## 3. 功能需求

> 优先级说明：Must = 首版必须交付；Should = 首版做但可空/次要；Could = 首版候选；Won't = 首版明确不做。
> 字段「可空」不等于「可缺失」：字段必须存在，值可以为空；主名称等明确标注为必填的除外。

### 3.1 多作品管理

| ID | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-01 | 创建作品：填写作品名称（必填、全局唯一）与简介（可选）；创建后自动生成内置「境界」类别（必开、不可停用/删除）；用户可新增自定义体系类别 | Must | 两本作品可存在同名人物且互不冲突 |
| FR-02 | 顶部作品切换器：切换、编辑、删除作品；删除整本进回收站，需输入作品名确认并自动快照；恢复时整本恢复 | Must | 切换后数据完全隔离；删除/恢复可执行 |
| FR-03 | 作品是数据边界：所有实体属于且仅属于一本作品；第一版禁止跨作品引用；检索只在当前作品内 | Must | 跨作品无引用；检索不返回其他作品数据 |

### 3.2 人物档案

| ID | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-04 | 人物字段：主名称（必填、同一作品内唯一）、别名（多值）、称号（多值）、境界（主境界 + 可选子层级）、所属势力/分支（0..1）、1 张主图、简介、大事记 | Must | 字段完整；任一别名或称号可检索；图片可上传与预览 |
| FR-05 | 体系类别字段按作品启用的类别动态显示；内置「境界」类别必开、名称固定，但人物境界可空；停用类别不显示、不可选 | Must | 未启用类别的字段不出现在表单与详情页 |
| FR-06 | 人物详情：首屏展示主名称、别名/称号、境界、所属势力、主图；下方展示关系（势力、地点、榜单、体系引用）与大事记 | Must | 关系双向可跳转；无死链 |
| FR-07 | 删除人物：被引用时阻止并列出引用；无引用时进回收站，toast 可立即撤销 | Must | 被引用人物无法删除；无引用人物可恢复 |
| FR-08 | 主名称唯一，别名与称号允许重复；重复时检索结果返回多条，并显示实体类型、所属势力、主名称消歧 | Must | 同名别名不阻塞保存；结果可区分 |

### 3.3 势力

| ID | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-09 | 势力树：单棵树、父级可空、深度不限；种族作顶层节点；节点不区分「族/分支」类型，由名称表达 | Must | 可建立「万族 → 族 → 分支」层级 |
| FR-10 | 首领：每个节点 0..1 个人物引用，可空；成员由人物归属自动推导；势力页可按「仅直属 / 含下级」切换 | Must | 首领与成员展示正确；改名/换势力后自动更新 |
| FR-11 | 势力详情：名称、上级、下级分支、首领、成员、简介、关联地点、势力大事记 | Must | 关系双向；大事记可增删改 |
| FR-12 | 删除势力：有下级或被人物引用时阻止并列出引用；无引用时进回收站；恢复时若父级已删则阻止并提示先恢复父级 | Must | 删除/恢复规则可验证 |

### 3.4 地点

| ID | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-13 | 地点树：父级可空、深度不限；类型为自由文本并带已有值建议；简介可空 | Must | 可建立「星域 → 星城 → 秘境」层级 |
| FR-14 | 关系：人物 → 地点 0..N（带可选备注）；地点 → 势力 0..N（带可选备注）；双向展示 | Must | 人物页与地点页互相可达 |
| FR-15 | 删除地点：有下级或被引用时阻止并列出引用；无引用时进回收站 | Must | 删除/恢复规则可验证 |
| FR-16 | 地点详情：名称、类型、上级、下级、关联人物、关联势力、简介；本版不做地点图片 | Must | 详情页字段完整 |

### 3.5 榜单与席位

| ID | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| FR-17 | 榜单管理：数量不限、名称自定义且同一作品内唯一；创建时设定席位数 1–200（默认 100）；只可扩容；缩容仅当尾部席位全空，否则阻止并列出占用人 | Must | 可创建 100 席榜单；扩容/缩容规则生效 |
| FR-18 | 席位规则：席位号 1..N 固定即名次；允许空缺；每席 0..1 人物；同一人物同榜仅 1 席、可上多榜；调整用「移动到空席 / 与目标席位交换」；不做并列，备注可写「并列」 | Must | 可调整顺序；空缺可见；一人多榜可查 |
| FR-19 | 榜单详情：席位列表、空缺席位、在榜人物、备注；人物详情展示所在榜单与名次 | Must | 榜单与人物双向可达 |

### 3.6 体系设定

| ID | 需求 | 优先级 | 验收要点 |

| FR-26 | 体系页：类别列表（新增、改名、停用、删除、类型标识）、层级树、节点增删改排序、引用数量提示 | Must | 配置后人物表单立即生效 |

## 4. 业务流程

### 4.1 首次使用与新建作品

1. 打开应用，默认进入检索页；无作品时显示空状态与「新建作品」入口。
2. 新建作品：填写名称（必填、全局唯一）与简介（可选）→ 保存。
3. 系统自动生成内置「境界」类别（必开、不可停用/删除）；用户可进入体系页新增自定义类别（如星命、圣体）并配置层级。
4. 顶部切换器选中新作品；此后可录入势力、人物、地点、榜单，或进入导入向导。

### 4.2 日常检索

1. 确认顶部当前作品。
2. 在检索页输入关键词，或切换条件检索并选择筛选条件。
3. 结果按实体类型分组；点击结果进入对应详情页。
4. 在详情页通过关系链接跳转到关联人物、势力、地点、榜单或体系节点。
5. 无结果时显示明确提示与调整建议，不生成不存在的内容。

### 4.3 人物录入、编辑与删除

1. 人物列表 → 新建人物。
2. 填写主名称（必填）、别名、称号、所属势力/分支（可空）、境界（可空）、1 张主图、简介、大事记；其他体系类别字段仅在作品启用对应类别时出现。
3. 保存：校验主名称唯一、引用存在、图片格式；成功后进入详情页。
4. 编辑：详情页「编辑」进入内联编辑；改名、换势力、改境界后，所有关联页面与检索结果同步更新。
5. 取消编辑：有未保存修改时弹窗确认放弃。
6. 删除：先检查引用；被引用则阻止并列出引用位置；无引用则进回收站，toast 可撤销。

### 4.4 势力维护

1. 势力页以树形展示；新建节点时选择父级（可空）、填写名称与简介。
2. 设置首领：从人物中选择，0..1，可空；成员由人物归属自动推导。
3. 页面可切换「仅直属成员 / 含下级成员」。
4. 移动节点：不能移动到自身或自己的后代，否则阻止；移动后成员展示与关系链接同步。
5. 删除：有下级或被人物引用时阻止；无引用进回收站；恢复时父级已删则阻止并提示先恢复父级。

### 4.5 榜单维护

1. 榜单页新建榜单：名称（同一作品内唯一）、席位数 1–200（默认 100）。
2. 进入榜单详情：按席位号展示 1..N；空席显示「虚位以待」。
3. 指派人物：选择空席 → 搜索并选择人物 → 保存；同一人物同榜仅 1 席，若已在本榜其他席，提示先移出或交换。
4. 调整顺序：移动到空席，或与目标席位交换；席位号不变即名次。
5. 扩容：追加席位；缩容：仅当尾部席位全空，否则阻止并列出占用人。
6. 删除榜单：整张进回收站；恢复时若原席位人物已删除，阻止并提示先恢复人物。

### 4.6 体系配置

1. 体系页展示类别列表：内置「境界」标记「必开」，不可停用/删除；自定义类别显示类型（普通/纪元）与启用状态。
2. 新增类别：名称必填、同一作品内唯一、最多 10 类（含境界）；选择类型「普通」或「纪元」。
3. 停用类别前检查引用；有引用则阻止并列出引用数量与位置；无引用则停用，人物表单与详情页隐藏该字段，已有数据保留，可重新启用。
4. 删除类别：有引用则阻止；无引用时弹窗说明其下节点将一并删除，用户确认后类别与节点整组进回收站；恢复时整组恢复，名称冲突则阻止并提示改名。
5. 节点维护：每类最多两级；新增、改名、删除、同级排序；子层级为命名节点。
6. 删除节点：被人物引用时阻止；无引用进回收站；恢复时类别或父级缺失则阻止。
7. 改名：所有引用处与检索结果同步更新。
8. 纪元类型节点：名称 + 可选起止年份文本；按手工顺序展示，不做日期计算。

### 4.7 飞书迁移导入

1. 准备固定模板 Markdown 与图片 zip；模板包含作品信息、人物、势力、地点、榜单、体系、大事记与图片相对文件名。
2. 进入导入页，上传 Markdown 与 zip；系统解析并校验模板版本、必填字段、唯一性、引用关系、图片匹配。
3. 预览：显示各类实体数量、错误清单、图片匹配情况；有错误时不可确认导入。
4. 确认导入：在事务内原子写入新建作品；任一错误整批回滚；成功后生成导入报告。
5. 校对：实体标记「待校对」；在校对清单中按类型逐条确认；确认后取消标记；未确认实体在列表与详情有提示。
6. 迁移验收：实体数量、图片数量、层级抽查、校对记录、用户签收五项；报告留存。
7. 失败重跑：修正 Markdown/zip 后重新导入到新的空作品；不做增量 upsert。

### 4.8 备份、导出与恢复

1. 设置/备份页点击「导出」→ 选择是否包含回收站（默认包含）→ 生成 zip → 下载或显示文件路径。
2. 恢复：使用 CLI 脚本输入导出 zip；脚本先校验版本与完整性，再自动快照当前数据，最后覆盖恢复。
3. 恢复后执行 Smoke Test：启动、登录（N/A）、切换作品、检索、打开详情、检查图片。
4. 快照保留最近 3 份；恢复、导入、删除作品、清空回收站前自动生成快照。
5. 迁移前与公网部署前各执行一次空环境恢复演练，并留存记录。

### 4.9 删除与恢复

1. 删除任意实体前检查引用；被引用则阻止并列出引用位置。
2. 无引用则移入回收站；列表与检索立即隐藏；toast 提供撤销。
3. 回收站页可逐条恢复、永久删除或清空；永久删除与清空需二次确认并自动快照。
4. 恢复时校验名称冲突、父级是否存在、引用是否完整；不满足则阻止并给出下一步。
5. 删除作品：输入作品名确认 + 自动快照；整本进回收站，回收站中显示为一条作品项；恢复时整本恢复，其下实体不单独恢复。

### 4.10 一致性修改

1. 改名：只改一处；人物、势力、地点、榜单、体系节点、检索结果自动更新。
2. 换势力：人物归属变更后，原势力成员列表减少、新势力成员列表增加；首领引用不变。
3. 改境界：人物详情、检索结果、按境界筛选自动更新。
4. 所有修改走统一完整性校验；不允许复制文本或手工同步多处。

### 4.11 核心场景（Given/When/Then）

#### SC-01 新建作品并首次配置

- Given 本地服务已启动且当前无作品
- When 用户新建作品并填写唯一名称，进入体系页
- Then 系统自动创建内置「境界」类别（必开、名称固定、不可停用/删除），用户可新增自定义类别并配置两级节点
- And 切换作品后，列表、检索与关系只显示该作品数据

#### SC-02 检索人物并跳转

- Given 当前作品已存在人物「司空摘天」，别名「神逆」、称号「山海帝君」
- When 用户输入任一名称执行快速搜索
- Then 结果按实体类型分组，显示匹配字段摘要、所属势力与链接
- And 点击结果进入人物详情，可继续跳转势力、地点、榜单与体系节点

#### SC-03 改名后全局同步

- Given 人物已被势力成员、榜单席位与地点关系引用
- When 用户在人物详情内联编辑中修改主名称并保存
- Then 人物页、势力页、地点页、榜单页与检索结果全部显示新名称
- And 不产生旧名称残留或死链

#### SC-04 榜单席位调整与缩容阻止

- Given 已创建 100 席榜单，人物在第 3 席
- When 用户将人物移动到第 8 空席
- Then 第 3 席变为空席，第 8 席显示该人物，人物详情显示新名次
- And 当尾部席位仍有人时执行缩容，系统阻止并列出占用人

#### SC-05 体系类别与节点维护

- Given 作品已启用自定义类别「圣体」，且有人物引用其节点
- When 用户尝试停用或删除该类别
- Then 系统阻止并列出引用数量与位置
- And 删除无引用类别时，弹窗说明其下节点将一并删除，确认后类别+节点整组进入回收站并可整组恢复

#### SC-06 导入成功与失败

- Given 用户按固定模板整理《正文》并准备图片 zip
- When 上传并进入校验预览
- Then 系统显示实体数量、错误清单与图片匹配情况
- And 无错误时确认后原子写入新建作品并生成报告；有错误时禁止确认，目标作品无半成品数据

#### SC-07 删除引用保护与回收站恢复

- Given 某势力被人物引用，某人物在榜单有席位
- When 用户尝试删除该势力或人物
- Then 系统阻止并列出引用位置
- And 删除无引用实体后进入回收站，toast 撤销可恢复；恢复冲突时允许在弹窗内改名或提示先恢复父级

#### SC-08 导出与空环境恢复

- Given 当前已有完整数据，用户选择导出（默认包含回收站）
- When 系统生成全量 zip，用户在空环境执行 CLI 恢复
- Then 恢复前自动快照，恢复后数据、关系、图片、体系、榜单、大事记与导出前一致
- And 恢复失败不覆盖现有数据；恢复演练记录留存

### 5.2 页面交互

#### 5.2.1 全局

- 顶部固定作品切换器；切换作品时若当前有未保存修改，先确认。
- 侧边导航固定入口；当前页面高亮；页面标题与当前作品名称可见。
- 所有破坏性操作（删除、清空回收站、恢复、覆盖导入）必须二次确认，并在确认文案中说明后果。
- 所有列表与详情页显示「待校对」标记（如适用）。

#### 5.2.2 检索页

- 默认模式为快速搜索；输入框获得焦点。
- 快速搜索：输入后 300ms 自动检索，或按回车立即检索；允许 1 个字符。
- 条件检索：关键词 + 实体类型、势力/分支、境界、地点、榜单等筛选；点击「检索」执行。
- 结果按人物、势力、地点、榜单、体系节点分组；每组显示数量。
- 每条结果显示：名称、类型、匹配字段摘要、所属势力（人物）、链接。
- 分页每页 20；显示总数。
- 空查询：提示「输入名称、别名、称号或选择筛选条件」；不发起请求。
- 无结果：显示「未找到匹配条目」，列出当前关键词与筛选条件，建议减少关键词或清除筛选。
- 加载中：结果区骨架屏；输入框与按钮保持可用，避免重复提交。
- 请求失败：显示错误信息与「重试」；保留输入内容。

#### 5.2.3 人物列表与详情

- 列表默认按更新时间倒序；可按名称、更新时间排序。
- 筛选：所属势力/分支、境界、待校对状态；搜索框为当前列表内过滤。
- 分页每页 20；显示总数。
- 新建按钮固定可见；空状态显示「新建第一个人物」与导入入口。
- 详情页首屏：主名称、别名/称号、境界、所属势力、主图；主图缺失显示占位与上传入口。
- 关系区：所属势力、关联地点、所在榜单与名次、体系引用；全部可点击跳转。
- 大事记：按手工顺序展示；每条含文本与可选时间标签；可新增、编辑、删除、排序。
- 编辑：点击「编辑」进入内联编辑；保存/取消；保存时校验唯一性与引用。
- 未保存离开：弹窗「放弃未保存的修改？」。
- 删除：被引用时阻止并列出引用；无引用时进回收站并提供撤销。

#### 5.2.4 势力与地点

- 势力树默认展开两级；支持搜索节点名称并定位；切换「仅直属成员 / 含下级成员」。
- 势力详情显示上级、下级、首领、成员、关联地点、大事记；首领可点击进入人物详情。
- 地点树按父子层级展示；类型筛选；地点详情显示上级、下级、关联人物、关联势力。
- 势力与地点列表显示待校对标记，并可按待校对筛选。
- 新建/编辑使用内联表单；父级选择器支持搜索；禁止选择自身或后代作为父级。
- 删除规则与恢复规则同第 4.9 节。

#### 5.2.5 榜单

- 榜单列表显示名称、席位数、已占席位数、更新时间与待校对标记；新建入口固定可见。
- 榜单详情按席位号展示 1..N；每页 50 席，可翻页或跳转席位号；空席显示「虚位以待」。
- 每席显示：席位号、人物（可点击）、备注、操作。
- 指派：选择空席 → 搜索人物（本作品内）→ 确认；若人物已在本榜其他席，阻止并提示先移出或交换。
- 调整：移动到空席，或与目标席位交换；席位号不变即名次。
- 扩容：在尾部追加席位；缩容：仅当尾部全空，否则阻止并列出占用人。
- 并列不单独建模；备注可写「并列」。
- 删除榜单：整张进回收站并二次确认。

#### 5.2.6 体系配置

- 类别区展示内置「境界」（标记「必开」，不可停用/删除）与自定义类别（显示类型与启用状态）。
- 自定义类别操作：新增、改名、停用、删除；新增时填写名称、选择「普通/纪元」；最多 10 类（含境界）；名称同一作品内唯一。
- 停用类别：先显示引用数量与位置；有引用则阻止；无引用才可停用；停用后人物表单隐藏、已有数据保留。
- 删除类别：有引用则阻止并列出引用；无引用时弹窗说明其下节点将一并删除，确认后整组进回收站；恢复时整组恢复，名称冲突阻止并允许改名。
- 节点树：显示主层级与子层级；支持新增、改名、删除、同级排序；最多两级。
- 纪元类型节点：名称 + 可选起始/结束年份文本；按手工顺序展示。
- 每个节点显示被人物引用数量；删除被引用节点时阻止并列出人物。
- 配置保存后，人物表单与详情页立即生效。

#### 5.2.7 导入向导

- 步骤条：上传 → 校验预览 → 确认导入 → 导入报告 → 校对清单。
- 上传区支持拖拽或选择：固定模板 Markdown + 图片 zip；提供模板下载与示例文件。
- 校验预览显示：各类实体数量、错误清单（按行/字段）、图片缺失/多余清单、模板版本。
- 存在错误时「确认导入」禁用；错误必须可定位到 Markdown 行号或字段。
- 确认导入：原子写入新建作品；失败不创建作品或整批回滚。
- 导入报告：作品名称、实体数量、图片数量、耗时、错误数、文件名、时间；报告留存可查看。
- 校对清单：按人物/势力/地点/榜单/体系分组；显示待校对数量；逐条进入详情确认；支持批量确认但需二次确认。
- 导入中禁止重复点击；显示阶段进度（解析/校验/写入/图片）。

#### 5.2.8 回收站

- 回收站为全局页面，展示所有作品的删除项；支持按类型、原作品筛选；整本删除的作品显示为一条作品项，其下实体不单独列出；删除的自定义体系类别显示为一条类别项，其下节点不单独列出，恢复时整组恢复。
- 列表列：类型、名称、原作品、删除时间、删除前父级、操作；类型覆盖作品、人物、势力、地点、榜单、体系类别、体系节点、大事记。
- 恢复：先校验名称冲突、父级存在、引用完整；冲突时允许在恢复弹窗中修改名称；父级缺失时提示先恢复父级。
- 永久删除：二次确认 + 自动快照。
- 清空回收站：二次确认 + 自动快照；显示将删除的数量。
- 删除项不参与列表、检索与关系跳转。

#### 5.2.9 设置/备份

- 导出：按钮 + 「包含回收站数据」复选框（默认勾选）；生成后提供下载/文件路径。
- 快照列表：时间、大小、路径、状态；保留最近 3 份；提供恢复命令说明。
- 恢复为 CLI：页面只展示命令模板与注意事项，不提供上传恢复。
- 显示版本号、数据目录、最近一次导出/恢复时间。
- 危险操作（清空回收站、删除作品）不在设置页重复提供入口。

#### 5.2.10 作品切换器

- 下拉展示所有作品；当前作品高亮；作品数量多时可按名称搜索（Should）。
- 新建作品：名称必填、全局唯一；简介可选；创建后进入体系页并提示配置境界。
- 编辑作品：改名需唯一校验；简介可改。
- 删除作品：输入作品名确认 + 自动快照；整本进回收站；若删除当前作品，自动切换到另一作品或空状态。
- 切换作品时若有未保存修改，先确认。

### 5.3 通用状态与反馈

| 场景 | 行为 |
|---|---|
| 空数据 | 显示说明 + 下一步入口（新建/导入）；不显示空白页 |
| 加载中 | 列表/详情用骨架屏；按钮禁用；长任务显示阶段进度 |
| 请求失败 | 显示错误信息 +「重试」；保留用户输入与未保存编辑 |
| 保存成功 | Toast 提示 + 数据刷新；停留在当前页 |
| 权限不足 | 本版 N/A（无角色/无登录） |
| 网络中断 | 提示「无法连接本地服务，请确认 Docker 容器正在运行」+ 重试；不提供离线模式 |
| 重复提交 | 保存/导入按钮提交后禁用；服务端唯一约束兜底；不产生重复记录 |
| 并发修改 | 使用 updated_at 乐观锁；冲突提示「数据已被其他页面修改，请刷新后重试」；不自动合并 |
| 用户取消 | 有未保存修改时确认「放弃未保存的修改？」；取消后恢复原值 |
| 数据异常 | 字段级错误提示；悬空引用阻止；导入错误清单；恢复冲突阻止 |
| 删除被引用 | 阻止并列出引用位置；提供跳转到引用处 |
| 删除无引用 | 进回收站 + toast 撤销 |

- 本版不做自动保存；保存为显式操作。
- 所有错误提示使用中文、说明原因与下一步，不展示堆栈或内部 ID。

### 5.4 响应式与可访问性

- 桌面优先：以 1280px 及以上为主要设计宽度；最低保证 1024px 可用。
- 不做移动端专门适配；小于 1024px 不保证体验。
- 支持最新版 Chrome / Edge；不承诺 IE 与旧版浏览器。
- 中文界面；键盘可完成主要操作，焦点可见；颜色对比满足基本可读性，不追求正式无障碍认证。

> 本版无用户表、无角色表、无审计日志表、无回收站独立表；软删除通过删除标记实现。
> 技术实现（数据库、表结构、索引）不在本文定义，由架构阶段确认。

| 关系 | 基数 | 一致性规则 |

| 人物 → 势力/分支 | 0..1 | 只能引用当前作品节点；被引用势力删除时阻止 |
| 势力 → 首领 | 0..1 | 首领必须是当前作品人物；人物删除时阻止 |

| 人物 → 地点 | 0..N | 多对多；带备注；双向展示 |

| 人物 → 体系节点 | 每类别 0..1 | 只能引用该作品已启用类别的节点；停用/删除被引用类别或节点时阻止 |

### 6.6 导入模板要求（固定模板 v1）

模板只接受以下区块与字段；字段值使用固定分隔符，精确语法由随功能提供的模板文件定义。示意：

- 类型：普通
- 启用：是 | 否
- 节点：
  - <主层级名称>
    - <子层级名称>

### 类别：<纪元类别名称>
- 类型：纪元
- 启用：是 | 否
- 节点：
  - <纪元名称> | <起始年份文本> | <结束年份文本>

## 势力
### <势力名称>
- 上级：<势力名称> | 无
- 首领：<人物主名称> | 无
- 简介：<文本>
- 大事记：
  - [<时间标签>] <文本>

模板规则：

- 必须包含模板版本标识；缺失或版本不支持 → 错误。
- 区块顺序固定；未知区块 → 错误。
- 引用一律使用「主名称」；同一文件内解析；无法解析 → 错误。
- 别名/称号/多值字段使用 `|` 分隔；值内不得包含 `|`。
- 「境界」类别必须存在且类型为普通；人物「体系引用」中的类别名称必须在「## 体系」中定义且启用；引用停用或未定义类别 → 错误。
- 类别最多 10 类（含境界）；每类最多两级；纪元类型节点可带起止年份文本。
- 榜单席位按席位号升序；空缺可省略或写「空」。
- 图片使用 zip 内相对路径；不得使用绝对路径或 `..`。
- 长文本字段不支持跨行；需要跨行时由模板定义的续行语法处理（实现阶段确认）。
- 模板文件与示例文件作为交付物提供；用户按模板整理飞书内容。

> 模板 v1 的精确语法（分隔符、转义、续行、空值写法）由随功能交付的模板文件固定，并附一份真实片段样例；实现前需与《正文》真实片段核对。

### 6.9 数据保留、隐私与安全

- 数据默认本地存储；本版不上传云端、不调用云端大模型、不做遥测上报。
- 小说设定与人物图片按私密数据处理；导出包与快照包含完整内容，由用户自行保管。
- 日志不得记录完整设定正文；只记录操作类型、实体 ID、错误码与耗时。
- 所有用户输入按纯文本转义渲染；导入的 Markdown 不得执行脚本或注入 HTML。
- 上传 zip 必须校验路径穿越、文件类型、大小与数量；拒绝非法文件。
- 本地服务只监听 `127.0.0.1`；校验 Origin/Host，防止其他网页对本地服务发起跨站请求。
- 未来公网部署必须增加访问控制与 HTTPS；本版不实现。

## 7. 异常处理

| ID | 场景 | 触发条件 | 期望行为 | 验收 |
|---|---|---|---|---|
| EX-01 | 空数据 | 作品无人物/势力/地点/榜单/体系节点 | 显示说明与下一步入口（新建/导入）；不显示空白页 | 新作品可完成首次录入 |
| EX-02 | 加载中 | 列表/详情/检索请求未返回 | 骨架屏或进度提示；按钮禁用；不重复发起 | 慢请求下无重复记录 |
| EX-03 | 请求失败 | 服务错误/超时/校验失败 | 中文错误信息 + 重试；保留输入与未保存编辑 | 失败后可重试成功 |
| EX-04 | 重复提交 | 连续点击保存/导入/删除 | 提交后按钮禁用；服务端唯一约束兜底；不产生重复实体 | 双击只产生一条记录 |
| EX-05 | 权限不足 | 本版无角色/无登录 | N/A；不实现权限提示 | 文档明确 N/A |
| EX-06 | 网络中断 | 本地服务不可达/容器停止 | 提示「无法连接本地服务，请确认 Docker 容器正在运行」+ 重试；不进入离线模式 | 恢复服务后可继续 |
| EX-07 | 并发修改 | 两个标签页同时编辑同一实体 | updated_at 乐观锁；后保存者收到「数据已被其他页面修改，请刷新后重试」；不自动合并 | 冲突可复现并提示 |
| EX-08 | 用户取消 | 编辑未保存离开/取消导入/取消删除 | 弹窗确认放弃；取消后保持原值；已提交的删除不因取消而撤销 | 不丢失已保存数据 |
| EX-09 | 数据异常 | 非法 ID、字段超长、引用不存在、名称重复 | 字段级错误提示；阻止保存；不写入半成品 | 异常输入无法入库 |
| EX-10 | 导入模板错误 | 缺版本、未知区块、字段缺失、格式不符 | 预览阶段报错，定位到行/字段；禁止确认导入 | 错误清单可定位 |
| EX-11 | 导入图片缺失 | Markdown 引用了图片但 zip 中没有 | 错误清单列出缺失文件；禁止确认导入 | 修正 zip 后可导入 |
| EX-12 | 导入引用无法解析 | 势力/人物/榜单引用名称不在文件内 | 错误清单列出引用与位置；禁止确认导入 | 修正后可导入 |
| EX-13 | 导入原子失败 | 校验通过但写入过程失败 | 整批回滚；不创建半成品作品；提示重试 | 目标作品无残留 |
| EX-14 | 删除被引用实体 | 人物/势力/地点/榜单/体系类别/体系节点被引用 | 阻止删除；列出引用位置并可跳转 | 无法制造死链 |
| EX-15 | 恢复冲突 | 回收站恢复时名称冲突/父级已删/引用缺失 | 阻止恢复；允许改名；提示先恢复父级 | 冲突可解决 |
| EX-16 | 停用类别有引用 | 停用自定义类别（如星命/圣体）但人物已引用 | 阻止停用；列出引用数量与位置 | 停用前必须先清空引用 |
| EX-17 | 缩容尾部有占用 | 减少席位数但尾部席位有人物 | 阻止；列出占用人 | 只能缩容空尾 |
| EX-18 | 移动成环 | 势力/地点移动到自身或后代 | 阻止并说明原因 | 树结构无环 |
| EX-19 | 榜单重复人物 | 同一人物在同一榜单已有席位 | 阻止指派；提示先移出或交换 | 同榜一人一席 |
| EX-20 | 席位越界 | 席位号 <1 或 >席位数 | 阻止保存；提示有效范围 | 无非法席位 |
| EX-21 | 名称重复 | 作品全局重名；同作品同类型实体重名；体系类别重名；体系节点同父重名 | 阻止保存；提示冲突对象 | 唯一性生效（英文不区分大小写） |
| EX-22 | 图片失败 | 格式不支持/超过 10MB/上传中断 | 阻止保存或提示重试；不写入残缺图片 | 非法文件不可入库 |
| EX-23 | 快照失败 | 恢复/删除作品/清空回收站前快照失败 | 阻止继续执行破坏性操作；提示原因 | 无快照不执行 |
| EX-24 | 恢复失败 | zip 损坏/版本不兼容/校验失败/磁盘不足 | 恢复前校验；失败不覆盖现有数据；保留快照 | 现有数据不受损 |
| EX-25 | 导出失败 | 磁盘不足/权限不足/生成中断 | 提示失败；不提供残缺 zip；可重试 | 无半成品导出包 |
| EX-26 | 页面/实体不存在 | 无效 URL、已删除实体、跨作品 ID | 显示「内容不存在或已删除」+ 返回入口；不显示堆栈 | 无死链、无内部信息泄露 |
| EX-27 | 检索无结果 | 关键词/筛选无匹配 | 明确提示；建议减少关键词/清除筛选；不编造 | 结果为空可解释 |
| EX-28 | 崩溃/断电 | 未保存编辑时进程中断 | 本版不提供草稿恢复；已保存数据不受影响；重启后可继续 | 已保存数据完整 |

> 所有异常提示使用中文，说明原因与下一步；不得展示堆栈、内部 ID 或英文报错原文。
> 破坏性操作遵循「先检查、再快照、后执行」；任何一步失败即停止。

| 图片上传 | ≤1s/张 | 单张 ≤10MB；本机；不含缩略图生成 | 抽样达标 |
| 首屏可交互 | ≤2s（硬验收） | 本机 Docker；1000 人物 | 手工计时；超标即验收不通过 |

- 性能数据以用户本机验收环境为准；不承诺云服务器或低配设备。
- 检索与列表必须分页；禁止一次性加载全部 1000 人物。
- 图片不得阻塞文字内容渲染；缩略图与懒加载为 Must，上传进度与可选压缩为 Should（见 9.2）。

### 8.2 可用性与可靠性

- 本地单用户工具，不承诺 99.9% 可用性；不以高可用架构为目标。
- 已保存数据在重启、容器重启后必须保留；数据目录通过 Docker volume 持久化。
- 崩溃或断电时，未保存的编辑可能丢失；本版不做草稿恢复。
- 服务不可达时给出明确提示与重试；不提供离线编辑模式。
- 无自动定时备份；用户手动导出；恢复/导入/删除作品/清空回收站前自动快照。
- 快照保留最近 3 份；快照生成失败时阻止破坏性操作。

### 8.3 容量

- 以第 6.7 节数据规模为验收基线；超出基线不承诺同等性能。
- 单作品 1000 人物、200 势力节点、200 地点、5 张榜单 ×100 席、10 类体系类别、150 体系节点、500 张图片（单图 ≤10MB）。
- 作品数量按 ≤10 设计（已确认，软上限）。
- 导入至少支持 1000 人物 + 500 图片的 Markdown + zip。

### 8.4 兼容性

- 验收环境：Windows + Docker Desktop；桌面浏览器最新版 Chrome / Edge。
- 主要设计宽度 1280px；最低 1024px；不保证小于 1024px 的体验。
- 不做移动端专门适配；不承诺 IE、旧版 Edge、Safari 旧版。
- 其他操作系统可运行 Docker 时不承诺验收，除非用户明确要求。

### 8.5 易用性与视觉

- 中文界面；术语与用户设定一致（人物、势力、地点、榜单、体系、大事记）。
- 核心操作路径不超过三步：检索 → 详情 → 关联跳转；新建 → 保存；导入 → 预览 → 确认。
- 所有页面提供空状态、加载状态、错误状态与下一步入口。
- 视觉为浅绿色渐变、简洁、信息优先；不使用装饰性动画干扰阅读。
- 所有按钮有明确结果；不出现占位文本、调试入口、未完成按钮。
- 视觉验收由用户本人确认。

### 8.6 可维护性与部署

- 通过 Docker 一条命令启动；数据目录可挂载；升级不得丢失数据。
- 不引入付费服务、云数据库、对象存储或云端大模型。
- 不引入运行时飞书依赖；迁移后系统可完全离线运行。
- 导出格式版本化；升级至少兼容上一版本导出包（具体策略架构阶段定）。
- 日志只记录操作类型、实体 ID、错误码与耗时，不记录完整正文。
- 启动日志可定位数据目录、端口与版本；设置页显示版本与数据目录。

### 8.7 安全

- 本版只监听 `127.0.0.1`；无登录、无角色；公网访问控制不在本版。
- 校验 Origin/Host，防止本地 CSRF；用户输入按纯文本转义，防 XSS。
- 上传 zip 防路径穿越；图片校验扩展名/MIME/大小/数量。
- 不上传云端、不做遥测；导出包与快照包含私密内容，由用户保管。
- 日志与错误页不泄露完整正文、文件路径或内部堆栈。
- 未来公网部署必须增加访问控制与 HTTPS；未实现前不得公网暴露。

### 8.8 可观测性

- 导入报告留存：文件名、作品、实体数量、图片数量、错误数、耗时、时间。
- 快照列表：时间、大小、路径、来源动作。
- 设置页显示：版本、数据目录、最近一次导出/恢复时间。
- 不接入 APM、不发送遥测；错误排查以本地日志与报告为准。

## 9. MVP 范围

| 关系与一致性 | 所有关系引用；双向跳转；无死链；改名/换势力/改境界同步；引用完整性校验 |
| 导入 | 产品内向导；固定 Markdown 模板 + 图片 zip；校验预览；原子导入；导入报告；全部实体的待校对清单；迁移范围仅《正文》与文档内现有配图 |

| 恢复 | CLI 脚本；校验、自动快照、覆盖恢复；失败不留半恢复状态 |
| 快照 | 恢复/导入/删除作品/清空回收站前自动快照；保留最近 3 份 |
| 回收站 | 作品/人物/势力/地点/榜单/体系类别/体系节点/大事记软删除；toast 撤销；逐条恢复/永久删除/清空 |
| 图片 | 人物主图 1 张；缩略图与懒加载；图片不阻塞文字渲染 |
| 页面与视觉 | 作品切换器 + 侧边导航；检索、列表、详情、榜单、体系、导入、回收站、设置；浅绿色简洁风 |
| 部署 | Docker 本地运行；数据持久化；浏览器访问；不依赖飞书运行时 |
| 异常与状态 | 空数据、加载、失败、重复提交、并发、取消、网络中断、数据异常均有明确行为 |

|---|---|
