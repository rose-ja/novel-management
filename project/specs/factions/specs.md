# factions — 势力树、首领与成员

- 域状态：`planned`（P6，2026-11-07）
- 目标行为：用单棵树表达势力层级，首领与成员由引用自动推导，删除遵守入向阻止矩阵。
- 关联页面：PG-04、PG-05；关联验收：AC-04、AC-09、AC-14。
- 说明：本文件中的 Spec 均为待实现目标，不代表当前系统能力。

## SPEC-FACTION-001 势力树、内联新建与搜索定位

- 状态：`planned`
- 来源：FR-09、FR-66；US-003；PG-04；API `GET/POST /api/v1/factions`；Data `factions`；AC-04
- 行为：
  - 单棵树、父级可空、深度不限；顶层通常为种族；节点不区分「族/分支」类型，由名称表达。
  - 新建/编辑使用页内内联表单，不新增独立编辑页；父级为树内选择器。
  - 默认展开两级；按节点名称搜索时自动展开祖先并定位，不隐藏层级。
  - 列表一眼看出名称、首领、直属成员数、下级分支数、待校对标记。
  - 名称在同作品内唯一、1–200 字符；空名称/重名阻止保存。
- 边界：
  - 不做多棵树、拖拽排序、跨作品移动。
  - 1000 节点规模按需求基线；树加载与搜索不阻塞页面。
- 验收场景：
  1. Given 空势力树，When 依次内联新建「万族 → 妖族 → 青丘」，Then 三级节点正确挂载，默认两级展开（E2E-03 / AC-04）。
  2. Given 树含 200 节点，When 搜索「青丘」，Then 自动展开祖先并高亮定位（PG-04）。
  3. Given 父级为自身或不存在，When 保存，Then 阻止并给出字段级错误（EX-09）。
  4. Given 同作品已有「妖族」，When 新建同名或大小写变体，Then `NAME_CONFLICT`（AC-17）。
- 变更历史：2026-11-07 — P6 新建，状态 `planned`。

## SPEC-FACTION-002 首领与成员推导

- 状态：`planned`
- 来源：FR-10、FR-34；US-003；PG-05；API `GET /api/v1/factions/{id}/members?scope=direct|subtree`、`PATCH /api/v1/factions/{id}`；Data `factions.leader_character_id`、`characters.faction_id`；AC-04
- 行为：
  - 每个节点 0..1 首领（人物引用，可空）；成员由人物的 `faction_id` 自动推导，不在势力内复制人物文本。
  - 势力页可切换「仅直属 / 含下级」；含下级时按树递归汇总，结果去重。
  - 人物改名或换势力后，首领/成员展示自动更新（同作品内）。
  - 首领不能是已删除人物；引用目标不可用时阻止设置并提示。
- 边界：
  - 不做副首领、职位、成员排序、成员批量移除。
  - 不做跨作品首领/成员引用。
- 验收场景：
  1. Given 节点设首领并有两个人物归属，When 查看详情，Then 首领与成员正确展示（AC-04）。
  2. Given 切换「含下级」，When 父节点有下级成员，Then 汇总包含下级且不重复（PG-05）。
  3. Given 人物改属另一势力，When 查看原/新势力详情，Then 两侧成员即时更新（AC-09）。
  4. Given 首领人物在回收站，When 查看节点，Then 标注不可用并提供引用定位（RT-13）。
- 变更历史：2026-11-07 — P6 新建，状态 `planned`。

## SPEC-FACTION-003 详情、关联展示与移动环校验

- 状态：`planned`
- 来源：FR-11、FR-35；US-003、US-008；PG-05；API `GET/PATCH /api/v1/factions/{id}`；Data `factions.parent_id`、`location_factions`、`chronicles`；AC-04、AC-09、EX-18
- 行为：
  - 详情展示名称、上级、下级分支、首领、成员、简介、关联地点、势力大事记。
  - 势力大事记复用大事记协议（SPEC-CHAR-007，`owner_type=faction`），与人物大事记同一 CRUD 与上限语义。
  - 关系双向可达：势力 ↔ 地点、势力 ↔ 人物；无死链。
  - 上级变更即节点移动；移动到自身或任一后代必须阻止并说明原因。
  - 编辑同页内联；未保存离开与并发冲突按 SPEC-PLAT-003。
- 边界：
  - 不做关系图谱；不做势力图片；不做跨层级排序。
  - 不做势力引用体系。
- 验收场景：
  1. Given 势力关联地点与人物，When 打开详情，Then 地点/人物链接均可到达对应详情（AC-09）。
  2. Given 把父节点移动到自己的后代，When 保存，Then 阻止并提示「不能移动到自身或后代」（EX-18）。
  3. Given 两个标签页编辑同一势力，When 后保存者提交，Then `VERSION_CONFLICT` 提示且无覆盖（EX-07）。
- 变更历史：2026-11-07 — P6 新建，状态 `planned`。

## SPEC-FACTION-004 势力删除与恢复约束

- 状态：`planned`
- 来源：FR-12、FR-37、FR-38；US-003、US-011；PG-05、PG-12；API `DELETE /api/v1/factions/{id}`；Data 引用列；AC-14、EX-14
- 行为：
  - 入向引用阻止删除：下级势力、成员人物（人物→势力）；阻止时列出全部引用位置。
  - 出向引用随删解除：首领引用（势力→人物）、地点-势力关系、势力大事记，不阻止。
  - 无入向引用时整组进入回收站（含大事记），返回 8 秒 `undo_token`。
  - 恢复时若父级已删除，阻止并提示先恢复父级；恢复后回到原父级。
- 边界：不做级联删除下级/成员；不做强制删除。
- 验收场景：
  1. Given 势力有下级节点，When 删除，Then 阻止并列出下级位置（E2E-03 / AC-14）。
  2. Given 势力仍有成员人物，When 删除，Then 阻止并列出成员；清空成员后可删除（AC-14）。
  3. Given 势力仅被地点关联或是人物首领，When 删除，Then 允许删除，出向引用解除（AC-14）。
  4. Given 恢复时父级已删除，When 确认恢复，Then 阻止并给出先恢复父级的路径（EX-15）。
- 变更历史：2026-11-07 — P6 新建，状态 `planned`。
