## SPEC-TRASH-001 软删除范围、隐藏与回收站列表定位

- 状态：`implemented-partial`（CHG-002 交付「作品」根类型；CHG-003 交付「体系类别」「体系节点」根类型、父级展示与类型筛选；CHG-004 交付「人物」根类型与父作品名；CHG-006 交付「势力」根类型、父级名与影响数；地点/榜单/导入批次类型、原作品/父级筛选与 `highlight` 引用定位见后续变更）
- 来源：FR-57、FR-61、FR-62；US-011；PG-12 §2/§4；API `GET /api/v1/trash?type=&work_id=&page=`；Data 各表 `deleted_at/deleted_root_id`；AC-13
- 行为：
  - 软删除实体：作品（整本）、人物、势力、地点、榜单、体系类别（整组含节点）、导入批次；大事记与关系随根隐藏。
  - 回收站按类型/作品筛选、分页、按删除时间倒序；每条显示名称、类型、所属作品、删除前父级、删除时间、根/子项。
  - 支持 `?type=<类型>&highlight=<id>` 从引用对话框定位，命中行高亮。
  - 回收站实体不进入列表、检索、关系链接与计数；仍参与入向引用检查。
- 边界：
  - 不做回收站保留期自动清理（本版永久保留直到手动清空）。
  - 不做跨作品恢复；不做回收站内编辑。
- 验收场景：
  1. Given 删除人物、势力、地点、榜单，When 打开回收站，Then 各类型分列、可筛选与分页（E2E-11 / AC-13）。
  2. Given 引用对话框显示「回收站中」，When 点击定位，Then `/trash?type=...&highlight=...` 命中并高亮（RT-13）。
  3. Given 回收站有人物，When 打开人物列表/检索，Then 不出现；引用检查仍能发现（FR-62）。
  4. Given 整本作品删除，When 查看回收站，Then 只显示根作品，子项折叠计数（PG-12）。
- 变更历史：2026-11-07 — P6 新建，状态 `planned`；2026-11-08 — CHG-002 交付作品根列表、类型筛选与分页，状态转 `implemented-partial`；2026-11-09 — CHG-003 交付体系类别/节点根类型、父级展示与筛选；2026-11-11 — CHG-004 交付人物根类型与父作品名（势力/地点/榜单/导入批次与 `highlight` 定位见后续变更）。

## SPEC-TRASH-002 删除撤销

- 状态：`implemented-partial`（CHG-002 交付作品根 8 秒一次性撤销令牌（过期 409 `UNDO_EXPIRED`；重复提交按 409 `ALREADY_DELETED` 拒绝，与场景 2「幂等成功」表述不一致）；CHG-003 交付体系类别/节点撤销；CHG-004 交付人物撤销；其他实体撤销随各域变更，检索文档重建见 CHG-009）
- 来源：FR-59；US-011；PG-12 §6；API `POST /api/v1/trash/undo`；Data `undo_tokens`（TTL 8s）；AC-13、EX-04
- 行为：
  - 删除成功后 Toast 提供「撤销」，令牌 8 秒有效；重复点击只生效一次。
  - 撤销只能恢复本次删除根；若期间产生引用/名称冲突，撤销失败并提示改为回收站恢复。
  - 撤销成功后实体与关系回到原位，检索文档重建。
  - 8 秒后 Toast 消失，实体保留在回收站可后续恢复。
- 边界：
  - 不做多步撤销、不做跨会话撤销、不做撤销删除大事记以外的全局栈。
  - 不延长 TTL。
- 验收场景：
  1. Given 删除人物，When 8 秒内点击撤销，Then 人物与关系恢复，列表与检索重新可见（E2E-11 / AC-13）。
  2. Given 同一撤销请求重放，When 第二次提交，Then 幂等成功，不产生重复实体（EX-04）。
  3. Given 删除后 8 秒已过，When 点击，Then Toast 已不可用，需去回收站恢复（FR-59）。
  4. Given 撤销时名称被他人占用，When 提交，Then 失败并引导到回收站解决冲突（EX-15）。
- 变更历史：2026-11-07 — P6 新建，状态 `planned`；2026-11-08 — CHG-002 交付作品根 8 秒一次性撤销（`UNDO_EXPIRED`/`ALREADY_DELETED`），状态转 `implemented-partial`；2026-11-09 — CHG-003 交付体系类别/节点撤销；2026-11-11 — CHG-004 交付人物撤销（其他实体撤销与检索重建见 CHG-009）。

## SPEC-TRASH-003 恢复规则、renames 与整组原子

- 状态：`implemented-partial`（CHG-002 交付作品根原子恢复、`422 RESTORE_CONFLICT` + `details.items` 与单名 `new_name` 改名；CHG-003 交付体系类别 `renames[]` 子节点改名、父级 active 校验与整组原子恢复；CHG-004 交付人物单实体恢复与改名；CHG-006 交付势力单实体恢复、父级缺失 `PARENT_DELETED`；其余实体与页面逐项改名见后续变更，检索/关系重建见 CHG-009）
- 来源：FR-60、FR-61；US-011；PG-12 §6；API `POST /api/v1/trash/{type}/{root_id}/restore`；Data `deleted_root_id`、名称约束；AC-13、AC-15
- 行为：
  - 单实体恢复：校验同级名称冲突；冲突时要求新名称（`new_name`/`renames[]`），解决后原子恢复。
  - 整组恢复（作品、体系类别、含子节点）：根与全部子项在单一事务内恢复；任一冲突未解决则全部不恢复。
  - 父级已永久删除或仍在回收站时，阻止恢复并提示先恢复父级（不自动跳级）。
  - 恢复后重建检索文档与关系；出向引用恢复原值。
  - 恢复界面展示冲突清单与逐项改名输入；单项恢复不生成快照（整组恢复同样不触发快照，除非包含作品根）。
- 边界：
  - 不做部分恢复、不做递归自动恢复父级、不做合并。
  - 不做恢复到其他作品。
- 验收场景：
  1. Given 人物名称已被占用，When 提供新名，Then 恢复成功且其他字段不变（AC-15）。
  2. Given 整组类别含 2 个冲突节点，When 只解决 1 个，Then 整组失败，无半恢复（AC-13）。
  3. Given 父级在回收站，When 恢复子节点，Then 阻止并提示先恢复父级（EX-15）。
  4. Given 恢复完成，When 检索原名称/新名称，Then 仅新名称命中，关系恢复（FR-60）。
- 变更历史：2026-11-07 — P6 新建，状态 `planned`；2026-11-08 — CHG-002 交付作品根原子恢复与单名改名，状态转 `implemented-partial`；2026-11-09 — CHG-003 交付体系类别 `renames[]` 子节点改名、父级 active 校验与整组原子恢复；2026-11-11 — CHG-004 交付人物单实体恢复与改名（其余实体与检索重建见 CHG-009）；2026-11-13 — CHG-006 交付势力恢复与父级缺失阻断。

## SPEC-TRASH-004 永久删除、清空、快照与跨回收站引用

- 状态：`implemented-partial`（CHG-002 交付作品根永久删除、`confirm=PURGE_ALL` 清空与操作前快照；CHG-003 交付体系类别/节点根永久删除、含软删子节点的父子顺序与引用阻断骨架；CHG-004 交付人物根永久删除与作品组联动、统一锁序；CHG-005 交付人物/作品永久删除时 `media_assets`/`chronicles` 行与磁盘文件清理；CHG-006 交付势力根永久删除、势力大事记清理、活跃成员复核与清空回收站容错；跨回收站引用完整验收见 CHG-012，检索文档清理见 CHG-009）
- 来源：FR-58、FR-63；US-011；PG-12 §6；API `DELETE /api/v1/trash/{type}/{root_id}`、`DELETE /api/v1/trash`；Data 物理删除 + 快照；AC-13、AC-14、EX-14
- 行为：
  - 永久删除单根 / 清空回收站前生成快照；快照失败阻止操作。
  - 永久删除仅清理回收站中的根及其子项；不触碰在线数据。
  - 永久删除后图片按引用计数清理，检索文档物理删除。
  - 跨回收站引用：在线实体引用回收站实体时仍阻止在线实体删除；被引用回收站实体不可永久删除，需先解除引用或恢复。
  - 永久删除确认文案明确「不可恢复，仅能通过快照」，并二次确认。
- 边界：
  - 不做定时清理、不做部分清空（按类型清空可选但需确认）。
  - 不做绕过引用的强制永久删除。
- 验收场景：
  1. Given 回收站人物被在线榜单席位引用，When 永久删除人物，Then 阻止并列出在线引用（E2E-15 / AC-14）。
  2. Given 回收站作品无在线引用，When 永久删除，Then 快照生成、数据物理删除、图片清理（AC-13）。
  3. Given 快照失败，When 清空回收站，Then 阻止并提示（EX-23）。
  4. Given 同一根重复永久删除，When 第二次提交，Then 返回已删除，幂等且无错误堆栈（EX-04）。
- 变更历史：2026-11-07 — P6 新建，状态 `planned`；2026-11-08 — CHG-002 交付作品根永久删除、清空与操作前快照，状态转 `implemented-partial`；2026-11-09 — CHG-003 交付体系类别/节点根永久删除、父子顺序与引用阻断骨架；2026-11-11 — CHG-004 交付人物根永久删除与作品组联动、统一锁序；2026-11-13 — CHG-005 交付图片/大事记行与文件清理（跨回收站引用见 CHG-012、检索清理见 CHG-009）。
