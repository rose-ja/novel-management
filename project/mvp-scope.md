## MVP 必须交付

| ID | 能力 | 用户价值 | 验收标准 | 优先级 |
|---|---|---|---|---|
| MVP-01 | 多作品管理：创建、切换、编辑、删除整本进回收站；作品名称全局唯一；数据与检索隔离；整本原子恢复，子实体冲突可逐项改名；不做跨作品引用 | 多本小说各自独立，不互相污染 | AC-01：两本作品可存在同名人物且互不冲突；删除/恢复可执行 | P0 |
| MVP-02 | 人物档案：主名称、别名、称号、境界（主境界 + 可选子层级）、所属势力/分支、1 张主图、简介、手工大事记（≤2,000 字） | 一个角色一份权威数据，别名/称号可查 | AC-02、AC-03、AC-33：字段完整；别名/称号可检索；图片可上传、预览、缩略图懒加载 | P0 |
| MVP-03 | 势力与地点：势力单棵树、节点不区分类型、首领与成员；地点单棵树、类型自由文本；人物-势力、人物-地点、地点-势力关系；删除按入向矩阵（势力被下级/成员阻止，地点被下级/人物地点/地点-势力关联阻止），出向引用随删解除 | 势力层级与地理关系清楚，成员自动推导 | AC-04、AC-05、AC-14：三级势力/地点树可建立；首领与成员正确；双向可达 | P0 |
| MVP-04 | 榜单与席位：名称自定义、席位 1–200（默认 100）、席位号即名次、空席、移动/交换、同榜一人一席、可上多榜、扩容/缩容、备注可写「并列」 | 榜单结构清晰，可查人物在哪些榜 | AC-06：100 席可创建；空席可见；同榜第二席被阻止；尾部有人时缩容被阻止 | P0 |
| MVP-05 | 体系设定：每作品一套；内置「境界」必开、名称固定、不可停用/删除；自定义类别 ≤10 类（含境界），类型普通/纪元，可新增/改名/停用/删除；每类最多两级；人物每类 0..1；势力不引用；类别+节点整组原子恢复，冲突子项可逐项改名 | 不同作品可使用不同体系；星曜/星命/圣体等名称不写死 | AC-07、AC-13、AC-14：自定义类别可用；境界不可停用/删除；被引用类别/节点删除被阻止；类别+节点整组进回收站 | P0 |
| MVP-06 | 当前作品检索：一个检索入口，快速搜索 + 条件检索；空格分词 AND；匹配名称/别名/称号/简介及关联实体名称；不检索大事记正文；不做同义词/拼音/错字容忍/语义理解 | 一次输入即可定位设定，结果可解释 | AC-08、AC-23：预设查询集命中正确；按类型分组、摘要、分页；不返回其他作品；P95 ≤150ms | P0 |
| MVP-07 | 关系双向跳转：人物、势力、地点、榜单、体系详情页展示入向与出向关系 | 从任一实体可达关联实体，无死链 | AC-09、AC-14：所有关联链接可达；存在入向引用时删除被阻止，出向引用随删解除 | P0 |
| MVP-08 | 一致性维护：关系用引用而非复制；改名、换势力、改境界一处修改，所有关联处同步（限当前作品） | 不再人工同步多处，避免矛盾设定 | AC-09：改名、换势力、改境界三类操作全部同步 | P0 |
| MVP-09 | 检索结果与摘要：返回匹配条目、摘要与链接；无匹配明确提示；不调用大模型、不生成内容 | 结果有出处，不编造；预期可控 | AC-08：预设查询集全部返回正确条目；无匹配提示正确 | P0 |
| MVP-10 | 飞书迁移：仅《正文》+文档内现有配图；产品内导入向导；固定 Markdown 模板（含体系类别段）+ 图片 zip（≤6GB，磁盘预检）；校验/预览/原子导入；可校对实体（人物、势力、地点、榜单、体系节点）待校对；导入报告留存（计数含体系类别数） | 现有设定与图片完整进入系统，可追溯可校对 | AC-10、AC-11、AC-18~AC-21：导入成功/失败行为正确；实体、图片、层级、校对记录五项完成 | P0 |
| MVP-11 | 数据导出与恢复：产品内全量导出 zip（可选含回收站，默认含）；CLI 还原；快照含 manifest/checksums 且可 `restore-snapshot`；恢复/导入/删除作品/永久删除/清空回收站前自动快照，保留最近 3 份，回收站单项恢复不快照 | 数据可备份、可恢复，迁移不丢数据 | AC-12、AC-22：空环境恢复成功；恢复前快照存在且可恢复；演练记录留存 | P0 |
| MVP-12 | 本地部署与单用户：Docker Desktop 启动；容器内监听 0.0.0.0、宿主仅发布到 127.0.0.1；本地数据持久化；本版不做公网访问 | 私密数据留在本机，零成本运行 | AC-29、AC-30：仅宿主 127.0.0.1 可达；无外部上传/遥测；重启后数据完整 | P0 |
| MVP-13 | 界面与视觉：浅绿色渐变、简洁、中文、桌面浏览器；页面覆盖检索、人物、势力、地点、榜单、体系、导入、回收站、设置/备份 | 信息一目了然，查找效率不被视觉拖累 | AC-27、AC-28：所有页面可达；无占位/调试入口；用户视觉确认 | P0 |
| MVP-14 | 数据完整性校验：必填、同一作品同类型主名称唯一、体系类别名称唯一、体系节点同父唯一、英文不区分大小写、禁止悬空引用、删除前按 6.10 矩阵查入向引用 | 正常入口无法制造重复或死链 | AC-17、AC-14：重复/缺失/越界被阻止；`Sword` 与 `sword` 视为重名 | P0 |
| MVP-15 | 回收站与撤销：作品、人物、势力、地点、榜单、体系类别、体系节点、大事记软删除；删除按 6.10 入向/出向矩阵；toast 撤销；逐条恢复/永久删除/清空；整组原子恢复且冲突子项可逐项改名；永久删除/清空前快照 | 误删可恢复，破坏性操作有底线 | AC-13、AC-14：删除后检索不到；撤销/恢复可用；冲突可解决；无死链 | P0 |

## MVP 明确不做

| 项目 | 不做原因 | 未来触发条件 |
|---|---|---|
| 小说正文、章节、大纲、发布 | 产品定位是设定资料库，不是写作工具 | 写作与设定引用成为高频刚需 |
| 关系图谱、可视化大屏、3D 展示 | 第一版优先解决查找与一致性；图谱不是主矛盾 | 数据密度足够且图谱能解决实际查找问题 |
| 多人协作、账号、权限、多租户 | 单用户起步；避免复杂度 | 开放公网只读访问或多人协作时另行设计 |
| 移动端 App 或专门适配 | 桌面浏览器优先；小于 1024px 不保证体验 | 真实移动使用场景出现 |
| AI 生成、续写、语义检索、云端大模型 API | 零成本约束；只做可解释的关键词/条件检索 | 有预算且建立人工审核流程 |
| 自动排名、战力计算、数值平衡 | 榜单只做手工席位；不做排名规则引擎 | 出现明确的自动化排名规则 |
| 跨作品引用、跨作品共享世界观 | 每本小说独立数据域 | 出现系列作品共享人物/势力的需求 |
| 飞书运行时依赖或双向同步 | 一次性迁移，避免同步冲突 | 飞书重新成为主要编辑入口（不建议） |
| 素材库迁移、图片批量导入 | 用户确认本版仅迁移《正文》+现有配图 | 提供素材库清单并有明确迁移需求 |
| 变更历史、审计日志、任意时点回滚 | 用备份/快照与回收站兜底 | 多人协作或误改风险显著上升 |
| 公网运营、计费、多语言/国际化 | 第一版不是公开产品，单用户中文场景 | 决定对外开放注册或出现非中文用户 |
| 通用低代码、自定义实体建模（体系类别自定义除外） | 防止范围膨胀 | 四类对象稳定后确有新实体需求 |

## V1 候选

> 来自原 Should 分级；首版可做，非验收阻断。不得挤占 MVP 必须项。

- 图片上传进度、可选压缩。
- 作品数量多时按名称搜索、最近使用排序。
- 列表更多排序字段、筛选条件记忆、每页条数切换。
- 快照下载、手动创建快照、快照说明。
- 导入报告导出为文件。
- 自定义标签、人物多图相册、变更历史、批量编辑。
- 势力/地点图片、自定义关系类型。
- 多套体系、跨作品检索、深色主题切换。

## V2 候选

> Later（V2 及以后）方向如下，不作为本版承诺；启动前必须另立需求与人工批准。

- 公网只读访问 + 访问控制 / HTTPS。
- 多人协作、账号、权限与多租户。
- 跨作品共享世界观与系列作品复用。
- 关系图谱与时间线可视化。
- AI 辅助检索/写作（需预算与人工审核流程）。
- 审计日志与任意时点回滚。
