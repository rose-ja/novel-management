## US-001 创建、切换与删除作品

作为项目发起人，我希望创建、切换、编辑和删除作品，以便多本小说各自拥有独立世界观且互不污染。

### 前置条件
- 本地服务已启动，浏览器可访问。
- 当前无作品，或已有至少一本作品。

### 主流程
1. 新建作品：填写名称（必填、全局唯一）与简介（可选）→ 保存。
2. 系统自动生成内置「境界」类别（必开、名称固定、不可停用/删除）。
3. 顶部切换器选中作品；切换后列表、检索、关系只显示当前作品数据。
4. 编辑作品名称/简介；名称需唯一校验。
5. 删除作品：输入作品名确认 → 自动快照 → 整本进回收站；恢复时整本原子恢复，子实体名称冲突可逐项改名（`renames[]`）。

### 异常流程
- 作品名称重复 → 阻止保存并提示冲突对象。
- 切换作品时有未保存修改 → 先确认放弃或继续编辑。
- 删除当前作品 → 自动切换到另一作品或空状态。
- 快照失败 → 阻止删除。

### 验收场景
- Given 两本作品各自存在同名人物，When 切换作品并检索，Then 只返回当前作品数据，无跨作品引用入口。
- Given 已有一本作品，When 删除并输入正确作品名，Then 生成快照、整本进入回收站，且可整本恢复。
- Given 恢复整本作品时其下多个子实体与现存实体重名，When 逐项改名后恢复，Then 整组原子恢复成功；若任一冲突未解决，Then 整组不恢复。
- Given 作品名已存在，When 新建同名作品，Then 保存被阻止并提示冲突。

### 权限与数据边界
- 单用户，无登录、无角色、无用户表。
- 作品是数据边界；所有实体只属于一本作品；第一版禁止跨作品引用与跨作品检索。

### 关联需求 ID
FR-01、FR-02、FR-03；AC-01、AC-13；MVP-01。

## US-002 录入、编辑与删除人物档案

作为项目发起人，我希望录入人物的主名称、别名、称号、体系引用、势力、主图与大事记，以便一个角色只有一份权威数据且可被任意名称检索。

### 前置条件
- 当前作品已存在；至少已有内置「境界」类别。
- 需要引用势力/地点/榜单时，对应实体已存在或允许为空。

### 主流程
1. 人物列表 → 新建人物。
2. 填写主名称（必填、同作品唯一）、别名、称号、所属势力/分支（可空）、境界（可空）、其他已启用体系类别（每类 0..1）、1 张主图、简介、大事记。
3. 保存时校验必填、唯一性、引用存在、图片格式/大小。
4. 详情页首屏展示主名称、别名/称号、境界、势力、主图；关系区展示势力、地点、榜单、体系引用与大事记。
5. 编辑采用内联编辑；改名、换势力、改境界后所有关联页面与检索结果同步。
6. 删除前按 6.10 矩阵检查入向引用：仅「势力首领」「榜单席位」阻止；普通势力成员归属、人物地点关系、体系节点引用随人物删除解除；无入向引用进回收站，toast 可撤销。

### 异常流程
- 主名称为空 → 阻止保存并提示。
- 同作品主名称重复 → 阻止保存；别名/称号重复允许，检索返回多条并消歧。
- 图片格式不支持、超过 10MB、上传中断 → 阻止保存或提示重试。
- 人物被势力首领或榜单席位引用 → 阻止删除并列出引用位置；仅为普通势力成员、有关联地点或体系节点引用时，不阻止，出向引用随删解除。
- 大事记文本超过 2,000 字 → 阻止保存并提示上限。
- 未保存离开 → 弹窗确认放弃。

### 验收场景
- Given 作品启用了「圣体」类别，When 打开人物表单，Then 出现「圣体」字段且最多选择一个节点；未启用类别不显示。
- Given 人物别名「神逆」、称号「山海帝君」，When 分别检索，Then 均能命中该人物并显示所属势力与主名称。
- Given 人物主图引用缺失或格式非法，When 保存，Then 保存被阻止并给出字段级错误。
- Given 人物在榜单上有席位，When 删除该人物，Then 删除被阻止并列出榜单与席位。
- Given 人物被设为某势力首领，When 删除该人物，Then 删除被阻止并列出势力首领位置。
- Given 人物仅为普通势力成员且有关联地点、体系节点引用，When 删除该人物，Then 不被阻止，出向引用随删解除并进入回收站。
- Given 大事记文本为 2,001 字，When 保存，Then 阻止保存并提示上限 2,000 字。
- Given 人物无入向引用，When 删除，Then 进入回收站且 toast 撤销可恢复。

### 权限与数据边界
- 单用户，无权限判断。
- 人物只属于当前作品；只能引用当前作品的势力、地点、榜单、体系节点。
- 主图仅 1 张；势力、地点本版不做图片。

### 关联需求 ID
FR-04、FR-05、FR-06、FR-07、FR-08；AC-02、AC-03、AC-14、AC-33；MVP-02。

## US-003 维护势力树、首领与成员

作为项目发起人，我希望以单棵树维护势力层级并设置首领，以便快速查看分支、首领与成员关系。

### 前置条件
- 当前作品已存在；需要首领时，人物已存在。

### 主流程
1. 势力页新建节点：选择父级（可空）、填写名称与简介。
2. 节点不区分「族/分支」类型，由名称表达；可建立「万族 → 族 → 分支」层级。
3. 设置首领：从当前作品人物中选择 0..1，可空。
4. 成员由人物归属自动推导；页面可切换「仅直属成员 / 含下级成员」。
5. 移动节点：不能移动到自身或后代；移动后成员展示与关系链接同步。
6. 删除：被下级势力或成员人物阻止；首领引用与地点关联随删解除、不阻止；无入向引用进回收站；恢复时父级已删则阻止并提示先恢复父级。

### 异常流程
- 父级选择自身或后代 → 阻止并说明原因。
- 删除有下级势力或有成员人物 → 阻止并列出引用位置；仅有首领或地点关联时允许删除，出向引用随删解除。
- 恢复时父级缺失 → 阻止恢复并提示先恢复父级。

### 验收场景
- Given 已建立「万族 → 族 → 分支」三级，When 打开势力树，Then 层级正确、可展开收起。
- Given 某人物归属分支，When 查看祖先势力并切换「含下级」，Then 该人物出现在成员列表。
- Given 设置首领，When 打开势力详情，Then 首领可点击进入人物详情。
- Given 势力仍有成员人物或下级势力，When 删除该势力，Then 被阻止并列出引用位置。
- Given 势力仅有首领与关联地点，When 删除该势力，Then 不被阻止，首领与地点关联随删解除并进入回收站。
- Given 将节点移动到自身后代，When 保存，Then 被阻止且树结构无环。

### 权限与数据边界
- 单用户；无权限判断。
- 势力只属于当前作品；首领与成员只能引用当前作品人物。
- 势力不引用体系；本版不做势力图片。

### 关联需求 ID
FR-09、FR-10、FR-11、FR-12；AC-04、AC-14；MVP-03。

## US-004 维护地点树与人物/势力关系

作为项目发起人，我希望维护地点层级并关联人物与势力，以便从人物页或地点页双向查看地理关系。

### 前置条件
- 当前作品已存在；需要关联时，人物或势力已存在。

### 主流程
1. 地点页新建节点：选择父级（可空）、填写名称、类型（自由文本，带已有值建议）、简介。
2. 建立「星域 → 星城 → 秘境」等层级。
3. 人物 → 地点 0..N（带可选备注）；地点 → 势力 0..N（带可选备注）。
4. 人物页与地点页双向展示关系并支持跳转。
5. 删除地点：被下级地点、人物地点关系或地点-势力关系阻止并列出引用；无入向引用进回收站。

### 异常流程
- 父级选择自身或后代 → 阻止。
- 删除有下级地点、被人物关联或被势力关联 → 阻止并列出引用位置。
- 类型为空 → 允许保存。

### 验收场景
- Given 已建立三级地点树，When 打开地点列表，Then 层级正确、类型筛选可用。
- Given 人物关联地点、地点关联势力，When 从人物页点击地点，Then 可达地点详情并可继续跳转势力。
- Given 地点被人物或势力关联，When 删除，Then 被阻止并列出引用位置；Given 地点有下级，Then 同样阻止。

### 权限与数据边界
- 单用户；无权限判断。
- 地点只属于当前作品；关系只能引用当前作品实体。
- 本版不做地点图片；地点不引用体系。

### 关联需求 ID
FR-13、FR-14、FR-15、FR-16；AC-05、AC-14；MVP-03。

## US-005 维护榜单与席位

作为项目发起人，我希望创建榜单并手工指派席位，以便查看名次、空缺与人物在榜情况。

### 前置条件
- 当前作品已存在；需要指派时人物已存在。

### 主流程
1. 新建榜单：名称（同作品唯一）、席位数 1–200（默认 100）。
2. 榜单详情按席位号 1..N 展示；空席显示「虚位以待」。
3. 指派人物：选择空席 → 搜索当前作品人物 → 保存；同榜一人一席，可上多榜。
4. 调整：移动到空席，或与目标席位交换；席位号即名次。
5. 扩容：尾部追加席位；缩容：仅当尾部全空。
6. 删除榜单：整张进回收站；恢复时若原席位人物已删除，阻止并提示先恢复人物。

### 异常流程
- 同一人物在同一榜单已有席位 → 阻止指派，提示先移出或交换。
- 席位号越界 → 阻止保存。
- 缩容尾部有占用 → 阻止并列出占用人。
- 恢复时人物缺失 → 阻止并提示先恢复人物。

### 验收场景
- Given 创建 100 席榜单，When 打开详情，Then 显示 1..100，空席可见，每页固定 50 席。
- Given 200 席榜单，When 跳转至第 120 席，Then 按每页 50 席定位正确（第 3 页）。
- Given 人物已在第 3 席，When 指派到第 7 席，Then 被阻止并提示先移出或交换。
- Given 移动人物到空席，When 保存，Then 席位号更新即名次更新，人物详情显示所在榜单与名次。
- Given 尾部席位有人，When 缩容，Then 被阻止并列出占用人。

### 权限与数据边界
- 单用户；无权限判断。
- 榜单与席位只属于当前作品；席位只能引用当前作品人物。
- 不做并列建模；备注可写「并列」；不做自动排名/战力计算。

### 关联需求 ID
FR-17、FR-18、FR-19、FR-20；AC-06、AC-14；MVP-04。

## US-006 配置体系类别与节点

作为项目发起人，我希望按作品配置体系类别与层级，以便不同小说可以使用境界、星命、圣体等不同设定而不写死。

### 前置条件
- 当前作品已存在；内置「境界」已自动创建。

### 主流程
1. 体系页展示类别列表：内置「境界」标记「必开」；自定义类别显示类型与启用状态。
2. 新增类别：名称必填、同作品唯一、最多 10 类（含境界）；选择类型「普通」或「纪元」。
3. 配置节点：每类最多两级；支持新增、改名、删除、同级排序。
4. 纪元节点：名称 + 可选起止年份文本；只按手工顺序展示，不做日期计算。
5. 停用类别：先查引用；无引用才可停用；已有数据保留，人物表单隐藏该字段。
6. 删除类别：有引用阻止；无引用时弹窗说明其下节点将一并删除，确认后类别+节点整组进回收站；恢复时整组原子恢复，节点名称冲突可逐项改名（`renames[]`）。
7. 改名：所有引用处与检索结果同步。

### 异常流程
- 超过 10 类 → 阻止新增并提示上限。
- 类别名称重复（英文不区分大小写）→ 阻止保存。
- 试图停用/删除内置「境界」→ 阻止。
- 停用/删除被引用类别 → 阻止并列出引用数量与位置。
- 删除被引用节点 → 阻止并列出人物。
- 恢复节点时类别或父级缺失 → 阻止。

### 验收场景
- Given 新作品，When 打开体系页，Then 存在内置「境界」，名称固定、必开、不可停用/删除。
- Given 新增「圣体」类别并启用，When 打开人物表单，Then 出现「圣体」字段；每类最多选择一个节点。
- Given 人物引用某类别节点，When 停用该类别，Then 被阻止并列出引用位置。
- Given 删除无引用的自定义类别，When 确认弹窗，Then 类别与其节点整组进入回收站，可整组原子恢复。
- Given 整组恢复类别时多个节点与现存节点重名，When 逐项改名，Then 整组恢复成功；任一冲突未解决则整组不恢复。
- Given 改名体系节点，When 查看人物详情与检索结果，Then 名称同步更新。

### 权限与数据边界
- 单用户；无权限判断。
- 体系类别与节点只属于当前作品；人物每类 0..1；势力不引用体系。
- 星曜/星命/圣体等名称由数据配置驱动，代码不得写死。

### 关联需求 ID
FR-21、FR-22、FR-23、FR-24、FR-25、FR-26；AC-07、AC-13、AC-14；MVP-05。

## US-007 在当前作品内检索设定

作为项目发起人，我希望用关键词或条件检索当前作品的人物、势力、地点、榜单与体系节点，以便一次输入即可定位设定。

### 前置条件
- 当前作品已存在且已有数据。
- 顶部已选中目标作品。

### 主流程
1. 默认进入检索页；快速搜索输入框获得焦点。
2. 输入关键词 → 300ms 自动检索或回车立即检索。
3. 空格分词 + AND；每个词必须命中实体名称/别名/称号/简介，或关联实体名称；不检索大事记正文。
4. 结果按人物、势力、地点、榜单、体系节点分组；每条显示名称、类型、匹配字段摘要、所属势力（人物）与链接。
5. 分页每页 20；显示总数。
6. 点击结果进入详情页；通过关系链接继续跳转。
7. 条件检索：实体类型、势力/分支、境界、地点、榜单等筛选，AND 组合。

### 异常流程
- 空查询 → 提示输入关键词或选择条件，不发起请求。
- 无结果 → 显示「未找到匹配条目」，列出关键词/筛选，建议减少关键词或清除筛选；不编造内容。
- 请求失败 → 显示错误与「重试」，保留输入。
- 加载中 → 结果区骨架屏；按钮禁用，避免重复提交。

### 验收场景
- Given 当前作品有「山海妖族 圣者境」相关人物，When 输入该组合，Then 返回正确条目并按类型分组。
- Given 当前作品与另一作品存在同名人物，When 检索，Then 只返回当前作品条目。
- Given 关键词无匹配，When 检索，Then 显示明确无结果提示，不生成不存在的设定。
- Given 1000 人物规模，When 执行检索，Then P95 ≤150ms，首屏可交互 ≤2s。

### 权限与数据边界
- 单用户；无权限判断。
- 只在当前作品内检索；不返回回收站数据；不返回其他作品数据。
- 不做同义词、拼音、错字容忍、语义理解、大模型生成。

### 关联需求 ID
FR-27、FR-28、FR-29、FR-30、FR-31、FR-32、FR-33；AC-08、AC-23、AC-32；MVP-06、MVP-09。

## US-008 关系一致性与双向跳转

作为项目发起人，我希望所有关系通过引用表达并可双向跳转，以便改名、换势力、改境界只改一处且不产生死链。

### 前置条件
- 当前作品已存在人物、势力、地点、榜单、体系节点及关系。

### 主流程
1. 人物→势力、人物→地点、地点→势力、势力首领、榜单席位、人物→体系节点均通过引用表达。
2. 各详情页展示入向与出向关系，链接可点击。
3. 改名、换势力、改境界后，人物页、势力页、榜单页、地点页与检索结果自动更新。
4. 删除实体前按 6.10 矩阵检查入向引用：存在入向引用时显示引用数量与位置并阻止；出向引用随删解除。

### 异常流程
- 删除存在入向引用的实体 → 阻止并列出引用位置；出向引用随删解除。
- 恢复时引用缺失 → 阻止并提示先恢复引用实体。
- 并发编辑冲突 → 使用 `version` + `If-Match` 乐观锁，提示「数据已被其他页面修改，请刷新后重试」，不自动合并。
- 页面/实体不存在 → 显示「内容不存在或已删除」+ 返回入口，不显示堆栈。

### 验收场景
- Given 人物改名，When 查看势力成员、榜单席位与检索结果，Then 新名称全部同步，无旧名称残留。
- Given 人物换势力，When 查看原势力与新势力，Then 原势力成员减少、新势力成员增加，首领引用不变。

- Given 从人物页跳转势力、从势力页跳回人物，Then 双向可达且无死链。

## US-009 飞书迁移导入与人工校对

作为项目发起人，我希望用固定模板和图片 zip 导入飞书《正文》，并在产品内校对，以便现有设定完整进入系统且可追溯。

### 前置条件
- 已按固定模板（含体系类别段）整理 Markdown；图片已整理为 zip（≤6GB）并按相对文件名引用。
- 目标为新建空作品；模板版本受支持。

### 主流程
1. 进入导入向导：上传 Markdown + 图片 zip（zip ≤6GB）；上传前执行磁盘空间预检，空间不足则阻止。
2. 解析并校验模板版本、必填字段、唯一性、引用关系、图片匹配与体系类别（模板必须含体系类别段；内置「境界」唯一，缺失时创建空内置）。
3. 预览显示各类实体数量（含体系类别数）、错误清单（按行/字段）、图片缺失/多余清单；类别、大事记、图片不参与校对但在此校验。
4. 无错误后确认导入：事务内原子写入新建作品；自定义类别按模板创建，体系节点按类别名归属。
5. 生成导入报告：文件名、作品、实体数量（含体系类别数）、图片数量、耗时、错误数、时间。
6. 可校对实体（人物、势力、地点、榜单、体系节点）标记「待校对」；在校对清单中逐条确认或批量确认（对 pending 原子确认），确认后记录 `reviewed_at` / `reviewed_by`（单用户为 `local-author`）。
7. 迁移验收五项：实体数量、图片数量、层级抽查、校对记录、用户签收。

### 异常流程
- 模板版本缺失/不支持、未知区块、字段格式不符 → 预览报错，禁止确认导入。
- 缺少体系类别段、类别名未定义、类别总数超过 10、出现多个/改名「境界」 → 预览报错，禁止确认导入。
- 模板缺失「境界」类别 → 不报错，导入时创建空的内置「境界」。
- zip 超过 6GB 或磁盘预检空间不足 → 阻止上传/导入并提示所需空间。
- Markdown 引用图片但 zip 缺失 → 错误清单列出缺失文件，禁止确认。
- 引用无法解析、重复主名称 → 错误清单列出位置，禁止确认。
- 写入过程失败 → 整批回滚；不创建半成品作品。
- 导入中重复点击 → 禁止重复提交，显示阶段进度。

### 验收场景
- Given 固定模板 + 图片 zip 完整正确，When 导入，Then 预览数量（含体系类别数）正确、原子写入成功、报告生成、可校对实体均为待校对。
- Given 模板含自定义类别且缺少「境界」类别，When 导入，Then 创建自定义类别与空的内置「境界」，节点按类别名归属，无重复境界。
- Given 缺少图片或重复主名称，When 预览，Then 错误可定位到行/字段，确认导入禁用，目标作品无半成品数据。
- Given zip 接近 6GB 且磁盘空间不足，When 上传，Then 磁盘预检阻止导入并提示所需空间。
- Given 导入成功，When 逐条或批量确认校对，Then 待校对标记消失，`review_status`、`reviewed_at`、`reviewed_by` 记录留存。
- Given 1000 人物文字内容，When 导入，Then ≤90s（不含大图拷贝），报告记录耗时。

### 权限与数据边界
- 单用户；无权限判断。
- 一次导入只写入新建空作品；不做增量 upsert；不做运行时飞书依赖。
- 仅迁移《正文》+文档内现有配图；素材库不纳入本版。

### 关联需求 ID
FR-39、FR-40、FR-41、FR-42、FR-43、FR-44、FR-45、FR-46；AC-10、AC-11、AC-18~AC-21、AC-25；MVP-10。

## US-010 导出、快照与恢复

作为项目发起人，我希望导出全量数据并在空环境恢复，以便迁移或误操作后数据可恢复。

### 前置条件
- 当前已有数据；本地磁盘可写；CLI 可执行恢复脚本。

### 主流程
1. 设置/备份页点击「导出」→ 选择是否包含回收站（默认包含）。
2. 生成 zip：数据清单、数据文件、图片目录、可选回收站目录；文件名含日期时间。
3. 提供下载或文件路径。
4. 恢复：CLI 输入导出 zip → 校验版本/完整性 → 自动快照 → 全量覆盖恢复；快照包含 manifest/checksums，可用 CLI `restore-snapshot` 恢复。
5. 恢复后 Smoke Test：启动、切换作品、检索、打开详情、检查图片。
6. 快照保留最近 3 份；CLI 全量恢复、导入、删除作品、永久删除、清空回收站前自动快照；回收站单项恢复不生成快照。
7. 迁移前与公网部署前各执行一次空环境恢复演练并留存记录。

### 异常流程
- 快照失败 → 阻止破坏性操作。
- zip 损坏/版本不兼容/校验失败/磁盘不足 → 不覆盖现有数据，保留快照。
- 快照缺失 manifest/checksums 或校验失败 → `restore-snapshot` 拒绝恢复并提示。
- 导出失败 → 不提供残缺 zip，可重试。
- 恢复失败 → 不留半恢复状态。

### 验收场景
- Given 含回收站与不含回收站两种导出，When 在空环境恢复，Then 数据、关系、图片、体系、榜单、大事记与导出前一致。
- Given 执行恢复，When 恢复开始前，Then 自动快照存在，且保留最近 3 份。
- Given 已有快照目录，When 执行 CLI `restore-snapshot`，Then 校验 manifest/checksums 后恢复到该快照状态。
- Given 损坏的 zip，When 恢复，Then 恢复被阻止，现有数据不受损。
- Given 空环境恢复完成，When 执行 Smoke Test，Then 启动、切换、检索、详情、图片均正常，演练记录留存。

### 权限与数据边界
- 单用户；无权限判断。
- 导出包与快照包含完整私密内容，由用户自行保管。
- 恢复为全量覆盖；本版仅支持 CLI 使用导出包或最近快照恢复，不做页面内任意时点回滚。

### 关联需求 ID
FR-52、FR-53、FR-54、FR-55、FR-56；AC-12、AC-22；MVP-11。

## US-011 删除、回收站与恢复

作为项目发起人，我希望删除实体时先检查引用，并可撤销、恢复或永久删除，以便误删不造成死链或数据丢失。

### 前置条件
- 当前作品存在待删除实体；已了解引用关系。

### 主流程
1. 删除前按 6.10 矩阵检查入向引用；被阻止则列出引用位置；出向引用随删解除。
2. 无入向引用则软删除进回收站；列表与检索立即隐藏。
3. toast 提供「撤销」；撤销即恢复，不依赖刷新。
4. 回收站按类型、原作品筛选；显示类型、名称、原作品、删除时间、删除前父级。
5. 恢复：校验名称冲突、父级存在、引用完整；单条恢复允许在弹窗内改名；作品/类别整组恢复允许对冲突子实体逐项改名（`renames[]`），整组原子恢复。
6. 永久删除：二次确认 + 自动快照；清空回收站：二次确认 + 自动快照并显示数量。
7. 删除作品：输入作品名确认 + 快照；整本进回收站，恢复时整本原子恢复；回收站单项恢复不生成快照。

### 异常流程
- 删除存在入向引用的实体 → 阻止并列出引用位置；出向引用随删解除。
- 恢复名称冲突/父级缺失/引用缺失 → 阻止并提示改名或先恢复父级。
- 快照失败 → 阻止永久删除或清空。
- 回收站数据不参与列表、检索与关系跳转。

### 验收场景
- Given 删除无引用人物，When 打开列表与检索，Then 该人物不可见；toast 撤销后恢复原位置。
- Given 删除自定义体系类别，When 确认弹窗，Then 类别与节点整组进入回收站，并整组原子恢复。
- Given 整组恢复时子实体名称冲突，When 逐项改名，Then 整组恢复成功；任一冲突未解决则整组不恢复。
- Given 恢复时名称冲突，When 在恢复弹窗改名，Then 恢复成功。
- Given 永久删除/清空回收站，When 确认，Then 自动快照存在且数据不可再恢复。

### 权限与数据边界
- 单用户；无权限判断。
- 回收站为全局页面，但数据仍归属原作品；恢复后回到原父级。
- 软删除覆盖作品、人物、势力、地点、榜单、体系类别、体系节点、大事记。

### 关联需求 ID
FR-57、FR-58、FR-59、FR-60、FR-61、FR-62、FR-63；AC-13、AC-14；MVP-15。

## US-012 页面、视觉与异常状态

作为项目发起人，我希望所有页面完整可用、状态明确、视觉简洁，以便日常查找不被空白页、错误或装饰干扰。

### 前置条件
- 本地服务运行；浏览器为最新版 Chrome / Edge；主要设计宽度 ≥1280px。

### 主流程
1. 顶部作品切换器 + 侧边导航（人物、势力、地点、榜单、体系、检索、导入、回收站、设置/备份）。
2. 默认进入检索页；所有页面可达；无仪表盘、无独立编辑页、无移动端页面。
3. 列表页提供搜索、筛选、排序、分页；空状态说明下一步操作。
4. 详情页首屏核心资料；关系、时间线、图片清晰；内联编辑；保存/取消；未保存离开确认。
5. 通用状态：空数据、加载中、请求失败、保存成功、网络中断、重复提交、并发修改、用户取消、数据异常均有明确行为。
6. 视觉：浅绿色渐变、简洁、中文、桌面优先；信息优先；图片缩略图懒加载不阻塞文字。

### 异常流程
- 空数据 → 显示说明 + 新建/导入入口，不显示空白页。
- 加载中 → 骨架屏/阶段进度；按钮禁用。
- 请求失败 → 中文错误 + 重试；保留输入与未保存编辑。
- 网络中断 → 提示「无法连接本地服务，请确认 Docker 容器正在运行」+ 重试；不提供离线模式。
- 重复提交 → 按钮禁用；服务端唯一约束兜底。
- 并发修改 → `version` + `If-Match` 乐观锁；提示刷新后重试，不自动合并。
- 权限不足 → 本版 N/A。
- 页面/实体不存在 → 明确提示 + 返回入口，不显示堆栈。

### 验收场景
- Given 新作品无数据，When 打开人物/势力/地点/榜单页，Then 显示空状态与下一步入口，无空白页。
- Given 两个标签页同时编辑同一人物，When 后保存者提交，Then 收到冲突提示，无静默覆盖。
- Given 1000 人物规模，When 打开首屏，Then 可交互 ≤2s；图片缩略图不阻塞文字渲染。
- Given 逐页检查，When 浏览所有页面，Then 无占位文本、无调试入口、无未完成按钮，视觉由用户确认。
- Given 服务停止，When 页面发起请求，Then 显示网络中断提示与重试，不进入离线模式。
- Given 仅本机访问，When 检查监听地址与外部请求，Then 容器内监听 `0.0.0.0`、宿主仅发布到 `127.0.0.1`，无外部上传/遥测。

### 权限与数据边界
- 单用户，无登录、无角色、无用户表；「权限不足」为 N/A。
- 本版容器内监听 `0.0.0.0`，宿主仅绑定 `127.0.0.1`；公网访问控制不在本版。
- 不做移动端专门适配；小于 1024px 不保证体验。
