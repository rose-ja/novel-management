# ADR-004: 软删除分组根模型（无独立回收站表）

- Status: Accepted（2026-11-07）
- Date: 2026-11-07
- Decision owner: 项目发起人；技术方案：架构师
- Database: PostgreSQL 16

## Context

FR-57~FR-63 要求：作品、人物、势力、地点、榜单、体系类别、体系节点、大事记均支持软删除；回收站列出类型、名称、删除时间、删除前父级；支持恢复、永久删除、清空；删除后从列表与检索隐藏；回收站数据不参与关系跳转。需求 §6.1 明确「本版无回收站独立表；软删除通过删除标记实现」。

关键场景：
- 删除作品时，其下全部实体应整本进回收站，恢复时整本恢复（FR-02）。
- 删除体系类别时，类别与其下节点一并删除，整组恢复（FR-21、PG-10 §6.1）。
- 删除人物/势力时，其大事记应随实体进回收站（FR-57/§6.4）。

## Decision Drivers

- 避免半删除状态：父记录已删、子记录仍可见会导致死链与检索泄漏。
- 恢复需要知道「这次删除动了哪些记录」。
- 回收站只应展示用户实际删除的根对象，而不是每个被级联标记的子记录。
- 不给所有表再加一张多对多回收站表，保持简单。

## Options Considered

| 方案 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| A. 独立 `trash_items` 表 | 删除时复制元数据到回收站表 | 回收站查询独立 | 数据重复、恢复需回写、易与实体表不一致 |
| B. 仅 `deleted_at` | 每表加删除时间 | 简单 | 无法表达级联与整组恢复；回收站需合并所有表；父删子未删风险 |
| C. `deleted_at` + `deleted_root_id`（推荐） | 每表加删除时间与根对象标识 | 单事务级联；回收站只查根；恢复按根整组 | 所有查询必须过滤 `deleted_at IS NULL`；根标识需正确维护 |

## Decision

采用 **C：`deleted_at` + `deleted_root_id`**。

规则：
1. 所有可软删除表统一包含：`deleted_at TIMESTAMPTZ NULL`、`deleted_root_id TEXT NULL`（根对象 ID）、`deleted_by_action TEXT NULL`（`delete` / `work_delete` / `category_delete` / `purge`）。
2. 用户直接删除的对象是「根」：`deleted_root_id = 自身 id`。
3. 级联时只标记**可软删除实体**：
   - 作品删除：该作品下人物、势力、地点、榜单、类别、节点、大事记、图片资产标记同一 `work_id` 根。
   - 类别删除：类别 + 其全部节点标记同一 `category_id` 根。
   - 人物删除：人物 + 其大事记 + 图片资产标记同根。
   - 势力删除：势力 + 其大事记标记同根。
   - 榜单/地点删除：仅根自身。
   - 关系表（别名、体系引用、人物-地点、地点-势力、席位）不加删除列，由父实体删除状态隐式隐藏；恢复后原样呈现。
4. 回收站列表只查询 `deleted_root_id = id` 的记录（即根记录），展示类型、名称、删除时间、删除前父级。
5. 恢复：按根取出整组，先校验名称冲突、父级存在、引用完整，再在同一事务内清空整组的 `deleted_at`/`deleted_root_id`/`deleted_by_action`。
6. 永久删除：先快照，成功后在单事务内物理删除整组；失败回滚；图片文件在事务提交后删除。
7. 所有业务查询、检索、关系跳转默认 `deleted_at IS NULL`；唯一索引使用 PostgreSQL 部分索引 `WHERE deleted_at IS NULL`。
8. `search_documents` 保留记录并置 `is_deleted = true`（不参与查询）；恢复时置 `false` 并重建文本。

## Consequences

- 正面：单事务保证整组一致；回收站不重复存储；恢复语义与用户心智一致（整本/整类）。
- 负面：每张表都需要两个列与查询过滤；级联逻辑集中在 `TrashService`，遗漏会导致脏数据。
- 约束：禁止任何模块自行写 `deleted_at`，删除/恢复必须经 `TrashService`。

## Risks and Mitigations

| 风险 | 缓解 |
|---|---|
| 某查询漏掉 `deleted_at IS NULL` 导致泄漏 | 统一 repository/query helper；集成测试覆盖每个列表与检索 |
| 根标识未维护导致回收站显示子记录 | 删除入口统一为 `TrashService`；本版不使用数据库触发器，靠 service + 集成测试 |
| 恢复时名称冲突 | 恢复前校验，冲突返回 `NAME_CONFLICT` 并允许改名后重试 |
| 作品恢复时部分引用已删 | 恢复校验引用完整，缺失则阻止并提示 |
| 永久删除物理级联顺序错误 | 固定删除顺序（检索文档 → 关系/席位 → 大事记 → 图片 → 节点 → 实体 → 类别 → 作品）并测试 |
| 引用检查漏掉回收站记录 | 引用检查包含回收站记录（C-07 已确认）；错误详情标注「回收站中」 |
