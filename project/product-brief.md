# Product Brief — 小说设定管理系统

> 阶段：P0 产品探索（模板对齐版）
> 状态：已按项目发起人既有确认结论整理；不新增产品决策。与 `requirements.md` 冲突时以需求基线为准。
> 上游来源：`PROJECT-SETUP.md`、`requirements.md`、`research.md`、`sources.md`
> 日期：2026-11-07

## 产品定位

小说设定的结构化资料库 + 检索与一致性维护工具。

- 为个人作者提供当前作品内的设定录入、检索、关系查看与一致性维护。
- 本地优先、单用户、零成本；不做小说正文写作、关系图谱、多人协作或 AI 内容生成。
- 产品是设定资料的唯一可信数据源；飞书文档在一次性迁移完成后归档。

## 目标用户

| 维度 | 内容 |
|---|---|
| 主用户 | 项目发起人本人：会同时构思多本小说、每本拥有独立世界观的个人作者 |
| 用户特征 | 已有大量飞书设定资料；能使用 Docker Desktop；接受本地部署与人工校对；追求零成本；重视详情完整性与视觉整洁 |
| 使用环境 | Windows + Docker Desktop；桌面浏览器（最新版 Chrome / Edge）；中文界面 |
| 本版非目标用户 | 普通读者、协作者、其他公开注册作者、多租户运营对象 |
| 未来用户 | 可能开放公网只读访问；本版不实现账号、权限与多租户 |

## 用户痛点

1. **查找成本高**：确认一个角色的势力、境界或榜单名次，需要在多个章节和列表之间翻找。
2. **同一实体多名称**：一个人物可能同时拥有本名、化名、称号和境界描述，没有统一主名称与检索入口。
3. **修改容易不一致**：改名、换势力、调整境界后需要人工同步多处，容易产生矛盾设定。
4. **迁移与丢失风险**：现有资料以「标题层级 + 括号备注 + 列表」混合表达，缺少统一字段；图片与层级容易在迁移中丢失。

## 核心价值

| 价值 | 说明 |
|---|---|
| 查得到 | 输入本名、别名或称号，一次检索定位人物，并看到境界、势力、所在榜单与图片 |
| 改一处全局同步 | 关系用引用而非复制；改名、换势力、改境界后所有关联页面自动更新 |
| 多作品隔离 | 每本小说拥有独立世界观、独立体系与独立数据；第一版禁止跨作品引用 |
| 迁移完整 | 飞书《正文》与现有配图一次性进入系统，层级可追溯、图片数量一致、可人工校对 |
| 数据可恢复 | 全量导出、CLI 还原、自动快照（保留 3 份）与回收站构成可靠性底线 |

## 核心使用场景

| 编号 | 场景 | 期望结果 |
|---|---|---|
| S1 | 写作者需要确认某个角色的完整设定 | 输入本名/别名/称号 → 检索结果 → 人物详情 → 境界、势力、榜单、图片、大事记 → 跳转关联实体 |
| S2 | 人物改名、换势力或调整境界 | 只改一处，人物页、势力页、榜单页与检索结果同步更新 |
| S3 | 开始构思一本新小说 | 创建作品 → 自动生成内置「境界」→ 配置自定义体系类别与榜单 → 录入人物/势力/地点，数据与旧作品完全隔离 |
| S4 | 调整榜单席位或人物名次 | 配置榜单名称与席位数 → 指派人物 → 移动/交换 → 查看空缺与在榜人物 |
| S5 | 首次把飞书资料迁入系统 | 按固定模板整理《正文》与现有配图 → 产品内导入向导（校验/预览/确认）→ 可校对实体（人物/势力/地点/榜单/体系节点）待校对 → 人工校对与签收 |
| S6 | 不想逐页翻找，想用关键词组合查询 | 输入关键词或条件（如「山海妖族 圣者境」）→ 返回匹配条目、摘要与链接；无匹配明确提示 |
| S7 | 迁移前或重大修改前备份 | 导出全量数据 → 在空环境验证恢复 → 留存恢复演练记录 |

## 成功指标

| 目标 | 成功标准 | 验收方式 |
|---|---|---|
| 查得到 | 输入任意本名、别名或称号，一次检索即可定位人物，并看到境界、势力与所在榜单 | 20–30 条真实人物样例逐条验证 |
| 改一处全局同步 | 改名、换势力、改境界后，所有关联页面自动更新 | 至少验证三类修改，检查人物页、势力页、榜单页 |
| 迁移完整 | 《正文》与现有配图中的人物、势力、地点、榜单、体系、图片完整进入系统，层级可追溯（素材库不纳入本版） | 迁移清单逐项核对；图片数量一致；抽查层级 |
| 替代飞书日常使用 | 完成一次真实创作准备流程，全程不打开飞书查设定 | 用户实际试用并确认 |
| 详情页完整 | 核心资料完整；关系双向可跳转；人物与势力有手工大事记；无死链 | 逐页检查 |
| 检索可用 | 预设查询集返回正确条目、摘要与出处；无匹配明确提示；不编造 | 预设查询集逐条验收 |
| 数据可恢复 | 全量导出后可在空环境恢复；迁移/恢复前有可用快照 | 执行一次完整恢复演练 |

## MVP 目标

- 完成人物、势力与地点、榜单、体系四类对象的结构化管理。
- 提供当前作品内的关键词/条件检索、关系双向跳转与一致性维护。
- 完成飞书《正文》与文档内现有配图的一次性迁移，并支持人工校对；素材库不纳入本版。
- 提供数据导出、CLI 还原与自动快照，确保迁移与日常使用不丢数据。
- 在本地 Docker 中单用户运行：容器内监听 `0.0.0.0`，宿主发布端口仅绑定 `127.0.0.1`；为未来公网部署保留访问控制扩展点，但本版不实现。
- MVP 明细见 `mvp-scope.md`。

## 非目标

| 项目 | 不做原因 |
|---|---|
| 小说正文、章节、大纲、发布 | 产品定位是设定资料库，不是写作工具 |
| 关系图谱、可视化大屏、3D 展示 | 第一版优先解决查找与一致性 |
| 多人协作、账号、权限、多租户 | 单用户起步；未来公网只读访问另行设计访问控制 |
| 移动端 App 或专门适配 | 桌面浏览器优先；小于 1024px 不保证体验 |
| AI 内容生成、续写、语义检索、云端大模型 | 零成本优先；只做可解释的检索与摘要 |
| 自动排名、战力计算、数值平衡 | 榜单只做手工席位与备注 |
| 跨作品引用、跨作品共享世界观 | 每本小说独立数据域 |
| 飞书运行时依赖或双向同步 | 一次性迁移后归档 |
| 素材库迁移与图片批量导入 | 用户确认本版仅迁移《正文》与现有配图 |
| 变更历史、审计日志、任意时点回滚 | 用备份/快照与回收站兜底 |
| 公网运营、多租户、计费、多语言 | 第一版不是公开产品，单用户中文场景 |

## 竞品与差异

| 竞品/替代方案 | 与本项目的关系 | 差异点 |
|---|---|---|
| Kanka | 领域模型最接近：campaign 作用域 + 实体 + 关系 + 导出 | 非中文网文专用；不建模榜单席位与境界层级；SaaS-first；许可证有限制 |
| World Anvil | 世界构建/写作平台，功能广度大 | 英文优先、SaaS、付费；未直接验证其结构化能力 |
| LegendKeeper | wiki + 搜索 + 离线 + 导出体验值得参考 | 不做结构化榜单与境界层级；Open Beta |
| Campfire | 模块化写作套件，写作 + 设定并重 | 本项目刻意只做设定，不承担写作功能 |
| 飞书 / Notion / Obsidian | 当前工作流上游与最强替代方案 | 缺少别名一等检索、引用一致性、榜单席位、每作品独立体系的组合能力 |

结论：本项目不以「功能更多」竞争，而以「中文网文设定 + 检索优先 + 引用一致性 + 本地零成本」的组合差异立足；必须保持范围克制，避免演化为通用世界构建工具。

## 已验证事实

- 【事实】飞书《正文》是世界观设定集，包含纪元史、星空地理、星曜/星命/十五境体系、三张榜单、万族传、人物与配图。
- 【事实】三张榜单在飞书中为 1–100 固定席位，目前基本为空；产品支持 1–200 席（默认 100）。
- 【事实】人物是多值实体：可同时拥有本名、化名、称号、境界（含重天等子层级），并归属势力或分支。
- 【事实】势力存在层级：万族 → 族 → 分支，分支下有首领与成员。
- 【事实】文档中已有真实人物配图；人物主图是实际需求。
- 【事实】当前资料依靠标题层级、括号备注与列表混合表达，没有统一字段。
- 【事实】项目发起人已确认：单用户本地 Docker、零成本、中文、桌面优先、仅迁移《正文》+现有配图、备份/导出为 Must。
- 【事实】项目发起人已确认：体系类别按作品自定义（≤10 类，含内置「境界」），星曜/星命/圣体等名称不得写死。

## 关键风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 检索预期落差 | 用户期待自然语言理解，实际只是关键词/条件检索 | 明确「检索 + 摘要 + 出处」定位；预设查询集验收；不承诺推理 |
| 迁移保真度不足 | 人物、势力、图片或层级丢失 | 固定模板 + 校验预览 + 数量核对 + 人工校对 + 用户签收 |
| 范围膨胀 | 演化为低代码平台或通用世界构建工具 | 最小配置边界；新增项必须人工批准 |
| 无审计/任意时点回滚 | 误改或误删后无法追溯 | 全量导出 + CLI 还原 + 自动快照（3 份）+ 回收站；重大操作前快照 |
| 多作品独立体系 | 数据模型复杂、页面易混用 | 每本作品独立数据域；第一版禁止跨作品引用 |
| 零成本与未来公网 | 公网托管可能产生费用 | 零成本只约束第一版本地使用；公网费用另行确认 |
| 模板整理成本 | 飞书排版不完全符合固定模板 | 提供模板、示例、校验预览与待校对清单；不承诺兼容任意原始排版 |
