- Status: Approved（2026-11-14，F1 按推荐方案批准）

- Related Spec: SPEC-RANK-001、SPEC-RANK-002、SPEC-RANK-003、SPEC-RANK-004

## Problem / Opportunity

CHG-004～007 已交付人物、势力、地点与回收站/撤销/快照基座，但榜单仍是空壳：后端没有任何榜单代码，前端没有 `/rankings` 路由，人物列表、人物详情与势力成员表的「榜单」列恒为「—」。用户无法用「席位号即名次」的方式维护排行榜，也无法从人物侧看到所在榜单，`rankings`/`ranking_seats` 在数据模型与 API 契约中一直处于未实现状态。

## User Value

- 用户可创建任意数量的榜单，并设定 1–200 个固定席位；空席始终可见，名次不会因空缺被压缩。
- 用户可以在榜单详情中指派人物、把人物移动到空席、与他人交换、移出榜单，并用备注记录「并列」等说明。
- 用户可从人物详情、人物列表、势力成员表三处直接看到「榜单名·第N席」并跳转到榜单，双向可达、无死链。
- 删除榜单安全可控：整榜进回收站、8 秒撤销、恢复时若原席位人物已删则阻止并提示先恢复人物；人物删除被榜单席位阻止，避免产生死引用。

## Goal

交付一条完整可走通的榜单垂直切片：迁移 `0008` 建立 `rankings`/`ranking_seats`；后端提供榜单 CRUD、固定席位、指派/移动/交换/移出、备注、扩容/缩容、删除/撤销/恢复/永久删除；前端提供 `/rankings` 列表与 `/rankings?id=` 详情，并在人物与势力侧同步名次；全量门禁与 E2E 通过。

## In Scope

- 迁移 `0008_rankings`：`rankings`、`ranking_seats` 两表与索引、CHECK、部分唯一索引。
- 榜单 CRUD：名称 1–200、同作品唯一（大小写等价）、席位数 1–200（默认 100）；列表搜索、待校对筛选、更新时间/名称排序、分页 20。
- 固定席位：建榜批量生成 1..N 空席；详情 50 席/页（允许 50/100）、跳至席位、摘要（席位数/已占/空席）、前三席预览。
- 席位操作：指派到空席、移动到空席、与目标席位交换、移出榜单；同一人物同榜仅 1 席（`SEAT_CONFLICT`）；备注 ≤500、可写「并列」。
- 扩容/缩容：扩容追加空席；缩容仅尾部连续空席，否则 `SEAT_SHRINK_OCCUPIED` 并列出占用人；越界 `SEAT_OUT_OF_RANGE`。
- 人物侧回显：人物详情、人物列表、势力成员表显示所在榜单与名次（最多 2 条 + `+N`）。
- 生命周期：整榜软删除 + 8 秒撤销；回收站 `root_type=ranking` 列表/恢复/永久删除；恢复校验席位人物存在（`REFERENCE_MISSING`）；人物删除被席位阻止（含回收站榜单）。
- 作品整组：作品软删除/恢复/永久删除/清空回收站覆盖榜单与席位，且不触发席位→人物 FK 违约。
- UI：列表/详情/四个对话框、空/加载/错误/冲突/引用阻断状态、1024/1280 响应式、a11y 与键盘可达。
- 文档：F10 回写 SPEC-RANK-001~004、`api-contract.md` §3.6/§3.3、`data-model.md`、roadmap 进度。

## Out of Scope

- 自动排名、智能排序、并列名次建模（备注可写「并列」）。
- 榜单模板、榜单分类、跨作品榜单、拖拽排序、批量导入席位（CHG-011 覆盖）。
- 校对确认端点 `POST /rankings/{id}/review`（与 CHG-006/007 一致，延后 CHG-011；本轮只读 `review_status` + Badge + 筛选）。
- 检索索引同步（CHG-009）、导出格式扩展（CHG-010）、榜单大事记/图片。
- 领域外的其他改动。

## Acceptance Criteria

1. 新建「封神榜」100 席：创建成功进入详情，席位 1–100 固定升序、全部为空；列表显示 100 席、已占 0、空席 100。
2. 席位数 0 或 201 被阻止并提示 1–200；同作品「封神榜」/「封神榜 」/大小写变体视为重名。
3. 指派人物到第 5 席成功；移动到第 12 席后第 5 席变空、第 12 席占用；与目标席位交换后两人互换且都不重复。
4. 同一人物已在第 3 席时再指派第 9 席被阻止（`SEAT_CONFLICT`），提示先移出或交换；同一人物可上多个榜单。
5. 详情每页 50 席；跳至 120 席按 `floor((120-1)/50)+1=3` 计算页码并高亮；`page_size` 仅 50/100。
6. 从 100 扩容到 120 后新增 20 个空席可见；从 150 缩容到 100 且尾部全空时成功；第 145 席有人时缩容被阻止并列出占用人。
7. 人物详情、人物列表、势力成员表均显示「榜单名·第N席」并可跳转到 `/rankings?id=`。
8. 删除榜单后整榜进回收站、人物侧不再显示该榜，8 秒内可撤销；恢复后席位、备注、名次原样恢复。
9. 若某席位人物已被删除（先删榜后删人），恢复榜单被阻止并提示先恢复人物。
10. 人物在榜单（含回收站中的榜单）任职时删除被阻止，`details.items` 含 `ranking_seat`、榜单名与席位号，可定位。
11. 作品删除/恢复/永久删除后榜单与席位不残留、无 FK 报错；两本作品榜单互不可见。
12. 1024/1280 无横向溢出；axe 无 serious/critical；空席可键盘指派、对话框焦点陷阱可用。

## Constraints and Assumptions

- 技术栈不变：Go + Gin + GORM + PostgreSQL + goose；Next.js 静态导出；不新增第三方依赖。
- 复用既有模式：软删除三件套、`version` + `If-Match`、`name_key = lower(trim(name))` 活跃唯一部分索引、8 秒 `undo_token`、回收站 `root_type`、`pg_advisory_xact_lock`。
- `rankings`/`ranking_seats` 当前不存在，无需迁移历史脏数据；席位无独立软删列（data-model §3.7）。
- 席位是榜单子行，可见性由 `rankings.deleted_at` 决定；删除榜单保留席位行，恢复原样呈现。
- 人物删除引用检查包含回收站中的榜单（恢复后仍需保持关系）。
- 榜单没有父级，回收站不展示父级列。

## Risks

| 风险 | 影响 | 缓解 |
|---|---|---|
| 交换触发 `seats_character_uq` 部分唯一索引 | 交换失败 | 同事务先两席置空再分别回写；锁两行；集成用例覆盖 |
| 作品永久删除被席位→人物 FK RESTRICT 阻断 | 永久删除/清空回收站 500 | 所有 purge 路径先删 seats 再删 rankings，再删 characters |
| 回收站榜单仍引用人物 | 人物被误放行删除 | 引用查询不过滤 `deleted_at`；Purge 前复核 |
| 缩容与席位写入并发交错 | 删掉已占席位 | 作品行锁 → ranking advisory → 榜单/席位行锁；缩容与 PUT 同序 |
| 移出榜单撤销破坏他人修改 | 覆盖并发编辑 | 前端快照 + version 校验，409 时只提示 |
| 席位分页与跳席计算偏差 | 跳错页 | 纯函数 `seatPage(seatNo, pageSize)` 单测覆盖 |
| 迁移 Down 丢数据 | 回滚损失 | Down 仅用于集成往返；迁移前快照 |
