# CHG-004 人物档案核心

- 变更 ID：`CHG-004-characters-core`
- 分支建议：`feat/chg-004-characters-core`
- 依赖：CHG-002（作品生命周期、快照、撤销）、CHG-003（体系类别/节点、`character_system_refs` 骨架、回收站三类根）
- 关联 Spec：SPEC-CHAR-001～005、SPEC-CHAR-008、SPEC-WORK-001（跨作品隔离收口）、SPEC-SYS-002/005（引用计数与 `in_trash` 收口）、SPEC-TRASH-002/003/004（新增「人物」根）
- 关联 Page Spec：PG-02（人物列表）、PG-03（人物详情）、PG-12（回收站类型筛选）
- 关联需求/验收：FR-04～FR-08、FR-44、FR-47、FR-48、FR-66、FR-67；AC-01、AC-02、AC-03、AC-14、AC-16、AC-17、AC-24；EX-04、EX-06、EX-07、EX-08、EX-21、EX-22
- 复杂度：L；状态：`approved`（F1 已获人工批准，2026-11-09）

## 1. 目标与用户价值

让用户在当前作品内完成人物档案的**首个完整业务闭环**：新建 → 列表浏览/搜索/筛选/排序/分页 → 详情查看 → 内联编辑（含动态体系字段、别名/称号）→ 安全删除 → 8 秒撤销与回收站恢复。

这是 CHG-001～004 里程碑的最后一块：完成后系统可启动、建多作品、配体系、维护人物并用回收站恢复，可开始真实试用。

## 2. 范围

### 2.1 In scope

1. **数据模型（迁移 0004）**：`characters`、`character_names`；为 0003 已建的 `character_system_refs` 补 `character_id` 外键；人物软删除三件套与部分唯一索引。
2. **人物 CRUD**：创建、列表（`q` 搜索主名称/别名/称号、境界筛选、待校对筛选、排序、分页）、详情、PATCH 全量替换 `names`/`system_refs`、软删除 + 8 秒撤销。
3. **动态体系字段**：按作品已启用类别生成 0..1 节点选择；节点必须属于该类别、类别必须启用；内置「境界」必开但人物可空；停用/未启用类别不出现。
4. **别名/称号**：多值、同人物内按 `kind + value_key` 去重、稳定排序、软上限 20（前端提示）。
5. **乐观锁**：`version` + `If-Match`；PATCH/DELETE 版本不一致 → 409 `VERSION_CONFLICT`，不自动合并。
6. **删除与引用框架**：入向引用检查框架（势力首领/榜单席位，当前无数据则通过，CHG-006/008 接入）；出向引用（体系引用、别名、未来地点/大事记）随人物软删除隐藏；跨作品隔离。
7. **回收站扩展**：新增 `character` 根类型（列表、类型筛选、恢复、永久删除、清空），恢复要求作品 active 且名称不冲突（支持 `new_name`）。
8. **体系引用计数收口**：引用清单补充人物名称与 `in_trash` 标注；回收站中的人物仍计入引用（删除类别被阻断并标注「回收站中」）。
9. **作品组一致性**：作品软删除/恢复/永久删除人员与人物联动（`deleted_root_id=work_id`）。
10. **前端**：`/characters` 列表页、`/characters?id=<id>` 详情页、新建 Drawer、内联编辑、未保存离开守卫、冲突对话框、删除/引用对话框、导航「资料 > 人物」。
11. **测试**：后端单测 + 集成（含 1000 人性能基线）、前端 vitest、Playwright E2E（列表/详情/删除/回收站/视口/a11y）。

## 5. 影响面

- **数据**：新增 2 表 + 1 外键；`character_system_refs` 由「无主骨架」变为真实引用；作品组删除/恢复/永久删除需覆盖人物。
- **接口**：新增 `/api/v1/characters*`；回收站接口扩展 `root_type=character`；体系引用 details 增加 `name`/`in_trash`。
- **前端**：新增 2 个路由与人物组件；导航新增入口；回收站类型筛选与 Badge 增加「人物」。
- **性能**：列表需索引与 SQL 分页；1000 人 P95 ≤500ms。
- **兼容**：不改既有作品/体系契约；`CharacterSummary` 相对 `api-contract.md` 增加 `names[]`（列表需展示别名/称号 chip），需在 F10 回写契约。

## 6. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 动态字段与类别停用/改名耦合 | 引用存 `category_id + node_id`，展示实时 join；停用类别拒绝写入（`CATEGORY_DISABLED`） |
| 乐观锁前端实现不一致 | 统一 `requestJson({ifMatch})`；409 统一 ConflictDialog；集成测试覆盖 |
| 回收站新增根类型破坏既有分页/排序 | 复用 CHG-003 的 `TrashItem` 结构；排序键保持 `deleted_at DESC, root_id DESC` |
| 引用计数把回收站人物算入导致「类别无法删除」困惑 | 引用清单返回 `in_trash` 并在对话框标注「回收站中」，与 RT-13 一致 |
| 1000 人性能不达标 | 组合索引 `(work_id, deleted_at)`、`(work_id, updated_at)`；`q` 用 `name_key LIKE` + `EXISTS` 子查询；集成实测 |
| 迁移不可逆 | 0004 Down 删除外键、`character_names`、`characters`；`TestMigrationRoundTrip` 覆盖 |

**回滚**：回退本变更提交 + 执行 0004 Down；人物数据可由删除前快照恢复；关闭导航入口与 `/characters` 路由；体系/作品功能不受影响。

## 7. 范围裁决（F1 已批准，2026-11-09）

| ID | 问题 | 裁决 |
|---|---|---|
| D1 | 势力/地点占位如何落地 | **纯占位，不建表**：`characters.faction_id` 为无 FK 的 TEXT，本轮仅接受 `null`；`location_links` 仅接受空数组。CHG-006/007 建表后补 FK（实施差异 F10 回写 data-model） |
| D2 | 校对端点是否本轮实现 | **延后 CHG-011**；DTO 只读返回 `review_status`/`reviewed_at`，列表 Badge 保留展示能力，详情不显示确认按钮（与 PG-03 AC 的已知差异记入 verification） |
| D3 | 人物回收站 | **本轮实现** `root_type=character`：列表/筛选/恢复/永久删除/清空 |
| D4 | 势力/地点/榜单占位呈现 | 列表不展示势力/地点筛选与榜单排序，榜单列固定「—」；境界筛选与待校对筛选可用；详情关系区显示对应空态 |

> 裁决结果已同步到 `design.md` §11 决策记录（D1～D9），无需再次确认。
